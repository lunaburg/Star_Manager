# Star_Manager 项目介绍

Star_Manager 是一个面向 HS2 / AIS 本地游戏目录的桌面资源管理器。它把人物卡、服装卡、zipmod、原版/模组物品、BepInEx 插件和资源诊断集中到一个 Electron 桌面应用中，通过本地 Python 后端建立可重建的索引，帮助用户查找、预览、整理和维护游戏资源。

本文是面向新用户、项目协作者和需要快速了解产品边界的人的入口文档。页面说明已根据当前可运行版本实际打开各主页面后的界面和无障碍文本核对；动态数量、目录状态和任务进度以用户本机显示为准。

如果希望先按界面截图快速浏览页面，可阅读[截图页面概览](page-overview-from-screenshots.md)；该文档按截图时间顺序提供一版更简短的页面导览。

![Star_Manager 品牌标志](../build-resources/brand-logo.png)

## 一句话理解

选择一个 HS2 游戏目录后，Star_Manager 会扫描 `mods/` 与 `UserData/chara/`，建立本地数据库，再通过多个页面提供浏览、诊断、导出和维护能力。

## 它主要解决什么问题

- 在大量角色卡中按目录、名称、标签和收藏状态查找内容。
- 在 zipmod 与模组物品之间切换浏览，查看作者、版本、状态、缩略图和来源包。
- 在物品浏览中查看当前游戏目录的原版服装/配饰，并通过装配模式与运行中的 HS2 角色状态联动。
- 发现缺失资源、缩略图异常、重复 GUID、坏包和角色卡依赖问题。
- 批量整理、导出或修复资源，并在运行日志中跟踪任务进度。
- 查看 BepInEx 插件的元数据、版本、依赖和诊断信息。
- 在独立工作台工程中维护模组 CSV 物品，选择数据库中的 Unity3D 物品作为模板，整理 `MainData` 并将资源写回工程；另保留 Sims 4 Package 到 FBX/PNG 的后端工具能力。
- 将删除的人物卡和 zipmod 放入可恢复的运行时回收站，并支持恢复或永久删除。

它不是联网的模组分发平台，也不执行 BepInEx DLL，不把本地成就上传到服务器。数据库、缩略图和预览文件属于可以重新生成的本地运行时缓存。

## 从页面理解产品

| 页面 | 主要用途 | 用户通常在这里做什么 | 需要注意的边界 |
| --- | --- | --- | --- |
| 开始游戏 | 设置游戏目录并启动 HS2 相关程序 | 选择目录、编辑并保存 `UserData/setup.xml`、启动游戏/工作室/VR、打开常用目录 | 保存会先生成 `.bak` 备份；同时检测 IPA 与 BepInEx 冲突 |
| 总览 | 查看资源库健康状况 | 查看角色卡、zipmod、物品数量，查看成就、建议操作和最近任务 | 数量来自本地索引；首次启动或索引变化时可能需要等待任务完成 |
| 卡片（角色/服装/场景） | 浏览角色卡、服装卡和场景卡 | 切换人物卡、服装卡或场景卡；人物卡支持按目录查找、搜索、查看详情、依赖、标签、收藏和批量操作；场景卡支持按目录浏览 PNG、查看横向预览、文件详情、依赖和远端模组补全 | 人物卡和服装卡各自受目录/索引状态影响；场景卡受 `UserData/studio/scene` 目录、文件状态和远端索引覆盖范围影响 |
| 模组管理 | 浏览 zipmod 与其物品 | 在模组浏览/物品浏览间切换，按使用状态、作者和状态筛选，查看详情、诊断、预览和维护入口 | 单对象操作与批量任务的确认和进度路径不同；移动/删除会影响游戏目录 |
| 插件管理 | 查看并管理 BepInEx 插件库存 | 搜索名称/GUID/DLL，查看版本、类型、状态、依赖、适用进程和诊断，打开 BepInEx 目录，单个启用或禁用插件 | 不执行 DLL；启停通过重命名 DLL 完成，游戏重启后生效 |
| 工作台 | 维护独立的模组制作工程 | 登记作者和工作空间、创建模组工程、管理 CSV 物品、从模组库选择 Unity3D 模板、整理 `MainData` 并写入工程；在工程工具栏中通过弹窗使用 Sims 4 Package → FBX | 工程 CSV 是工作台物品来源；模组级工具与物品级工具分层显示 |
| 运行日志 | 观察启动和任务过程 | 按类型筛选、搜索、清空、复制或导出日志，排查失败和进度问题 | 日志记录的是当前运行会话及任务消息，不替代后端接口文档 |
| 回收站 | 管理可恢复的删除项 | 按人物卡/模组筛选，恢复单项，永久删除单项或清空回收站 | 条目位于运行时 `trash/`；恢复模组后会重新建立单文件索引 |
| 设置 | 统一管理持久化偏好 | 选择启动页面、开关启动检查、选择收藏卡主题、管理成就、导出目录、便携包和 Blender 路径 | 设置影响后续启动和工具默认值；具体任务仍可能允许临时改目录 |

应用壳层统一维护当前 HS2 目录、目录校验结果、后端状态和数据库任务进度；开始页显示带目录选择和数据库重建的全局顶部栏；物品浏览将顶部栏用作类别筛选。总览、模组浏览、卡片、插件、工作台、日志、设置、回收站和物品装配模式按页面需要隐藏或替换该栏。

## 推荐使用流程

```mermaid
flowchart LR
    A["选择 HS2 目录"] --> B["目录有效 + Backend ready"]
    B --> C["检查或重建本地索引"]
    C --> D["总览确认数量与健康状态"]
    D --> E["浏览角色卡、模组和插件"]
    E --> F["复制式整理、导出或修复"]
    F --> G["运行日志跟踪任务结果"]
```

### 第一次打开

1. 在“开始游戏”或顶部共享区域选择 HS2 游戏目录。
2. 确认页面显示“目录有效”，并等待 `Backend ready`。
3. 如果页面提示索引不存在、过期或正在构建，等待任务完成；必要时使用“重建数据库”。
4. 打开“总览”确认角色卡、zipmod 和物品数量，再进入具体资源页面。
5. 第一次执行整理或导出时，优先保留“Copy”模式，先验证输出结果，再考虑移动操作。

### 日常整理

1. 在“卡片”中按目录、名称或标签找到目标人物卡，查看卡片详情和依赖；需要时切换到服装卡浏览器。
2. 在“模组管理”中先查看警告/错误数量，再选择 zipmod 或物品视图定位问题。
3. 对单个对象使用详情页提供的操作；对多个对象使用批量任务，并在“运行日志”观察进度。
4. 发现重复 GUID、缺失 Unity3D 或缩略图问题时，先查看诊断信息，再决定修复、导出、合并或删除。
5. 在“插件管理”中确认插件状态；需要调整时可对单个插件执行启用或禁用，完成后重启游戏。

## 各页面的实际能力

### 开始游戏

页面包含 HS2 目录选择、目录有效性提示、数据库任务状态、后端状态和三个启动入口：`HoneySelect2.exe`、`StudioNEOV2.exe`、`HoneySelect2VR.exe`。右侧快捷入口可打开游戏主目录、`UserData`、工作室场景、截图目录和男女角色卡目录。

页面中的游戏配置区域会读取并展示 `UserData/setup.xml` 的语言、画质、显示器、分辨率和全屏项。保存时会以 UTF-16 编码原子写回 XML、保留 `setup.xml.bak`，并同步 Unity 的显示器、分辨率、全屏和画质注册表值。存在 `IPA.exe` 时启动命令会经过 IPA；同时检测到 IPA 与 BepInEx 时会阻止启动并提示用户。

### 总览

总览把索引结果压缩为三个核心数量卡：角色卡、模组和模组物品。下方的本地成就陈列柜展示整理、修复和收藏里程碑；右侧建议操作当前提供外部模组导入、一键整理和重建数据库。最近任务区域用于确认目录检查、数据库构建等任务是否完成。

### 卡片管理

角色管理以 `UserData/chara` 为根，右侧目录树显示各目录及数量，中间区域提供当前目录/人物卡库切换、搜索和多选；场景卡从 `UserData/studio/scene` 独立浏览。选择角色卡或场景卡后可以进入详情查看依赖；人物卡还支持封面、基础信息、标签、收藏、评分和相关操作，场景卡支持地图、场景物品和图案依赖。原版服装和配饰可在依赖关联中按 `CategoryNo + ID` 显示为“游戏本体”；人物卡与场景卡的缺失模组依赖还可以查询远程索引并进入下载任务。

如果页面显示“未找到人物卡”，先确认当前目录是否正确、卡片索引是否完成，再切换到卡片库或重新选择目录。不要把某一个空目录的结果误认为整个 `UserData/chara` 没有卡片。

#### 人物卡侧边详情栏工具

![当前版本人物卡详情栏实机截图](assets/character-detail-screenshot.png)

> 实机截图：当前版本的“角色管理”页面，右侧详情栏已打开“关联”页签。截图中的卡片数量、路径、依赖数量和卡片内容会随本地游戏目录变化。

选中人物卡后，右侧栏可在“详情 / 关联 / 工具”之间切换。工具和信息的职责如下：

| 工具或区域 | 作用 | 写回/输出边界 |
| --- | --- | --- |
| 收藏星标 | 收藏或取消收藏当前人物卡；收藏主题会同步影响网格卡框和详情卡面 | 收藏元数据写入人物卡 PNG 的 `KKEx` 区块，不依赖 SQLite |
| 替换封面 | 选择 PNG/JPG/WebP，在 `63:88` 裁剪框中调整可见封面 | 只替换 IEND 前的可见 PNG，人物卡尾部数据和插件数据保留 |
| 评分 | 直接选择 1–5 星 | 保存当前人物卡评分 |
| 标签 | 添加、编辑或新建标签；批量标签在浏览器工具栏中处理 | 单卡直接写回；批量追加使用任务并保留原有标签 |
| 人物参数 | 编辑姓名、性格、生日、声线和 `futanari`；性别只读 | 写回当前 PNG，并在写回后重新校验卡片 |
| 关联 | 按服装、配饰、面部、发型、身体等部位查看依赖，区分已匹配、物品缺失和模组未安装 | 点击依赖项可跳转到对应物品或缺失处理流程 |
| 设为看板娘 | 将当前卡写入 `navi` 或 `sitri` 看板娘槽位 | 直接写入对应游戏目录的看板娘文件 |
| 导出为服装卡 | 将当前卡识别出的服装、配饰和坐标级插件数据导出为服装卡 | 可配置目录；未配置时按性别写入 `UserData/coordinate/female` 或 `male`，不会覆盖同名文件 |
| 生成便携依赖包 | 按选定依赖类型复制人物卡、匹配 zipmod、外部 Unity3D 和依赖清单 | 可输出 ZIP 或文件夹；只复制文件，不移动原始资源 |

### 模组管理

模组管理顶部显示 zipmod 数量、物品数量、warnings、errors 和最近索引时间。主区域有“模组浏览”和“物品浏览”两种视图，并支持已使用、未使用、全部等使用状态筛选；物品浏览还可以把当前游戏目录已索引的原版物品与模组物品合并查看，并按 Kind、作者、状态和搜索条件缩小范围。右侧详情面板承载 GUID、来源文件、诊断、缩略图、模型预览和维护操作；在物品浏览中还可进入装配模式，读取游戏当前角色/H 场景栏位并把已验证物品发送到游戏。

项目把 zipmod 作为包级对象、`abdata/list/**/*.csv` 解析出来的内容作为物品级对象。两者的数据库关系、重复 GUID 主副本规则和增量重建方式，统一以[模组数据库设计](mod_manage/mod_database_design.md)与[数据库变更检测](mod_manage/mod_database_change_detection.md)为准。

#### 模组物品侧边详情栏工具

> 实机操作路径：进入“模组管理”→“物品浏览”，选中一条物品记录后，在右侧详情栏打开“工具”页签。这里的工具会根据当前物品和本地资源状态显示 3D 预览、来源模组、Unity3D 文件打开、缩略图和删除等操作；本文不再使用示意图代替实机截图。

在“物品浏览”中选中一行后，右侧栏包含“详情 / 工具”两个页签：

| 工具或区域 | 作用 | 重要限制 |
| --- | --- | --- |
| 详情信息 | 查看来源模组、完整 GUID、物品 ID、分类表和依赖 Unity3D 文件 | 这是数据库和解析结果，不等于重新扫描文件 |
| 3D 模型预览 | 按需生成并加载模型，支持旋转、缩放、平移、背景和灯光预设；正方形预览区用于检查当前模型 | 面部、身体、姿势和图案不显示该预览。游戏专用 Shader 可能降级为标准材质；模型失败不应阻塞其他详情 |
| 定位来源模组 | 跳转到模组浏览并选中当前物品所属的 zipmod | 这是应用内定位，不是删除或移动操作 |
| 使用 SB3Utility 打开 | 通过设置页配置的 SB3Utility 可执行文件打开当前物品所属的 Unity3D 文件 | zipmod 内部文件会先准备运行时副本；不会导出 FBX、骨骼或蒙皮 |
| 重建缩略图 | 在外部 PNG 和当前 3D 预览截图之间选择来源并写回缩略图 | 使用 3D 截图前必须先成功加载模型 |
| 批量缩略图工具 | 导出当前物品缩略图，或选择当前已加载列表中的缺失缩略图物品并批量应用 | 仅普通物品显示；Studio 物品不显示该入口。批量应用使用任务协议，目标范围受当前加载/筛选列表限制 |
| 删除物品 | 删除当前 `mod_items` 记录及对应资源处理 | 会修改游戏目录和数据库，必须经过确认；执行前应备份 |

### 插件管理

插件管理扫描游戏目录下的 BepInEx 插件 DLL，并在列表中显示插件名称、GUID、版本、类型和启用状态。输入框支持按插件名称、GUID 或 DLL 搜索；选中一项后，右侧显示描述、依赖、适用进程和诊断信息，顶部按钮可以打开 BepInEx 目录。

Star_Manager 不执行 DLL，也不修改插件内容或配置。单个启用/禁用操作只会在 BepInEx 插件目录中将 `Example.dll` 重命名为 `Example.dl_`，或恢复原扩展名；历史 `.dll.disabled` 仅作为兼容状态读取，新的禁用操作一律使用 `.dl_`。目标文件已存在时不会覆盖，游戏重启后生效。

### 工作台

当前页面以独立模组工程为中心：

1. 首次进入时登记作者 ID 和工作空间。
2. 创建或选择一个模组工程；工程包含 `manifest.xml`、`star-manager.project.json` 和 `abdata/list/`。
3. 从类别 CSV 浏览或新建物品；新物品的 `MainData` 默认是 `<物品名>_obj`。
4. 在物品工作区通过“+”跳转到模组管理的物品工具页，选择可用 Unity3D 物品作为模板。
5. 读取候选 `MainData`，对运行时副本执行清理、复制或重命名，再将 Unity3D 复制到工程并更新当前 CSV 行。

Sims 4 Package → FBX 已接入工作台的模组工程工具栏，以弹窗选择 `.package`、输出目录并查看导出结果；详细输入输出约束记录在[工作台文档](frontend-ui/workbench-layout.md)中。

### 运行日志

运行日志以时间顺序展示后端启动、目录检查、数据库扫描、任务提交、进度、完成和失败消息。页面提供任务类型筛选、搜索、清空、复制全部和导出入口。处理大规模 zipmod 库时，日志是判断“仍在运行”“已完成”还是“失败退出”的首选位置。

### 回收站

回收站列出运行时 `trash/cards` 和 `trash/mods` 下的可恢复条目，可按人物卡或模组筛选。恢复人物卡会回到原记录路径；恢复模组会在源路径可用时重新执行单文件索引。永久删除和“清空回收站”才会移除回收站中的文件，页面不负责恢复无法验证的路径。

### 设置

设置页面按功能分为四组：

- 启动与检查：选择下次启动页面、控制启动时是否比较 zipmod/角色卡索引。
- 收藏人物卡主题：在鎏金流彩、霓虹炫彩、樱落绮梦和黑曜鎏火之间选择统一的卡框、铭牌字体、详情卡和动态效果。
- 本地成就：启用成就陈列柜、解锁通知、隐藏未解锁成就，或重置本地记录。
- 默认导出与 Blender：设置通用导出目录、服装卡导出目录、便携依赖包目录、ZIP 压缩偏好，以及 Blender 可执行文件路径和 RIG/AUTO IMPORT 集成。

收藏主题、成就和导出目录属于本地持久化设置，不会改变 zipmod 数据库本身。

## 数据与安全边界

- 所有索引、预览、日志和成就记录都存放在本地；运行时后端默认通过 `http://127.0.0.1:8765` 提供服务。
- SQLite、缩略图和卡片预览是可重建缓存。更换游戏目录或发现索引落后时，应通过应用重建，而不是手工编辑缓存文件。
- 文件操作默认使用 `Copy`。`Cut`、移动、合并和删除会改变游戏目录，执行前应确认目标和备份策略。
- 单个文件或对象使用直接 HTTP 路由；批量处理使用 `/tasks`，并通过任务状态和运行日志报告进度。接口细节见[前后端接口约定](backend-interface.md)。
- 插件页面只扫描元数据；角色卡依赖解析、zipmod 诊断和 Unity3D 修复属于不同的资源流程，不要把它们混为同一个“插件修复”功能。
- 游戏物品装配依赖用户确认游戏侧探针连接的是当前选择的 HS2 安装；应用不会替用户认证探针端口对应的游戏目录。

## 常见问题

### 为什么总览有数量，卡片或模组页面却暂时为空？

页面列表是异步分页加载的，且卡片管理还受当前目录/卡片库选择影响。先等待顶部任务和页面加载结束，再检查当前目录、搜索条件和筛选条件。

### 什么时候需要重建数据库？

首次选择目录、检测到 zipmod 或角色卡发生变化、列表与文件系统明显不一致，或日志提示索引过期时，可以执行重建。普通启动会先做变更检测，未发现变化时不必每次全量重建。

### 工作台为什么看不到 Unity3D 模板？

模板选择依赖模组数据库中存在可用的非地图物品，并且该物品的 `MainAB` 必须指向可读取的 `.unity3d`。先确认游戏目录已选择、数据库已完成构建，再从模组管理的物品工具页选择模板。

### 日志里的任务一直没有结束怎么办？

先确认任务仍在增加进度，再检查磁盘空间、游戏目录访问权限和日志中的具体异常。大规模 zipmod 库首次构建可能需要较长时间；不要在任务尚未完成时重复提交同一批量任务。
