# 开始页布局

## 当前职责

开始页是左侧导航第一项，当前已经接通：

- 选择并保存 HS2 游戏目录；
- 通过 Electron 启动 HS2、Studio 和 VR；
- 从启动操作条打开 Star_Manager 的 GitHub 仓库；
- 打开游戏主目录、`UserData`、工作室场景、截图和男女角色卡目录；
- 在目录入口末尾添加可自定义名称和路径的快捷目录按钮；
- 展示一个面向 `UserData/setup.xml` 的游戏配置面板。

开始页下方的游戏配置、启动器视觉卡和目录入口三个一级容器不显示外部黑色边框；配置控件保留各自边框，目录入口按钮使用透明磨砂玻璃表面和浅色边缘高光，不使用黑色外边框。

### 开始页三个容器移除外部边框记录（2026-09-12）

- 背景：开始页三个并列一级容器的黑色粗边框过重，与页面工作区边界形成重复分隔。
- 根因：游戏配置、启动器视觉卡和目录入口都继承了通用 `.panel` 的 `3px` 外部边框。
- 解决方案：为 `.start-columns` 下的三个直接面板增加开始页专属覆盖规则，设置 `border: 0`；内部表单控件、快捷入口按钮和视觉卡内容保持不变。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；三个一级容器外部边框消失，开始页启动流程、配置读写和目录打开行为保持不变。
- 适用边界：仅影响开始页 `.start-columns` 下的三个一级 `.panel`，不改变启动操作条或其他页面容器的边框样式。

### 开始页标题区移除底部分隔线记录（2026-09-12）

- 背景： “游戏配置”和“目录入口”标题下方的横线与开始页当前连续的半透明容器视觉不一致。
- 根因：两个标题区域使用通用 `.module-head`，该规则默认设置 `border-bottom: 1px solid var(--line)`。
- 解决方案：增加 `.start-view .module-head` 覆盖，将开始页标题区底边框设为 `0`；保留标题、说明文字、内边距和下方控件布局。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；开始页两个红框位置的横线消失，配置和目录入口功能保持不变。
- 适用边界：仅影响开始页两个 `.module-head`，不改变其它页面标题栏或开始页表单控件、目录按钮样式。

### 开始页目录入口副标题移除记录（2026-09-12）

- 背景：目录入口标题下方的“常用游戏目录快捷打开”文字与右侧按钮列表的功能含义重复，占用标题区域空间。
- 解决方案：移除目录入口 `.module-head` 内的副标题，仅保留“目录入口”标题和目录快捷按钮。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；副标题消失，六个目录打开入口和布局保持可用。
- 适用边界：仅影响开始页目录入口标题区域，不改变其它页面的 `.subtext`、目录按钮或路径逻辑。

### 开始页目录入口按钮移除黑色外边框记录（2026-09-12）

- 背景：截图标注的“游戏主目录”“UserData”“工作室场景”“截图”和男女人物卡目录按钮仍显示黑色外边框，目录入口区域视觉重量偏重。
- 根因：六个目录入口按钮通过 `.quick-list button` 继承并覆盖了通用按钮边框，只将边框宽度调整为 `1px`。
- 解决方案：将 `.quick-list button` 的边框设置为 `0`，保留按钮的背景、文字对齐、间距、禁用状态和目录打开逻辑。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；目录入口六个按钮不再显示黑色外边框。
- 适用边界：仅影响开始页右侧目录入口按钮，不改变游戏配置控件、保存配置按钮、启动按钮或其他页面按钮的边框。

### 开始页目录入口按钮改为透明磨砂玻璃记录（2026-09-12）

- 背景：移除黑色外边框后，目录入口按钮仍使用全局白色实心背景，与开始页整体的半透明壁纸和玻璃容器层次不一致。
- 解决方案：为 `.quick-list button` 使用浅白半透明背景、8px 背景模糊和轻微白色内沿/外发光；悬停和键盘聚焦时仅提高玻璃表面亮度与边缘光晕，不恢复黑色边框。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；六个目录入口按钮可透出后方背景，边缘保持低强度浅色高光，目录打开行为不变。
- 适用边界：仅影响开始页右侧目录入口按钮的背景和边缘质感，不改变按钮尺寸、文案、间距、禁用状态或其它页面控件。

其中 `setup.xml` 面板由 Electron 主进程负责读取和写回真实文件。读取失败时不会覆盖用户文件；保存会先生成 `UserData/setup.xml.bak`，再以 UTF-16 编码原子写入 `UserData/setup.xml`，并同步 HS2 使用的 Unity 注册表值。

### 自定义目录快捷入口（2026-09-15）

- **背景**：目录入口需要支持用户把常用的任意文件夹固定为按钮，截图红框位置作为新增入口。
- **解决方案**：在固定目录按钮后增加内联 SVG “+”按钮。点击后打开极简弹窗，使用目录选择器选择路径并填写按钮名；保存后写入管理器 `settings.json` 的 `directoryShortcuts`，并在目录入口列表中显示。自定义按钮直接调用现有 `openDirectory()` 能力，不依赖 HS2 游戏目录。
- **验证结果**：通过 `npm run build` 和 `git diff --check` 验证；固定入口、快捷项持久化和路径打开调用保持独立。
- **适用边界**：自定义快捷项只保存按钮名和目录路径，不创建目录、不移动文件，也不替代固定的六个游戏目录入口。

### 自定义快捷目录编辑与删除（2026-09-15）

- **背景**：自定义快捷目录创建后需要修改按钮名称、目录路径或移除按钮。
- **解决方案**：每个自定义快捷目录按钮右侧内部叠加编辑按钮，不额外占用快捷列表的一列；在通用快捷按钮左对齐规则之后，用更具体的选择器显式保持编辑图标在按钮内水平、垂直居中。编辑弹窗复用新增弹窗，支持重新选择路径和保存名称。删除操作直接删除 `settings.json` 中的快捷入口，不触碰实际目录或文件。
- **验证结果**：通过 `npm run build`、`npm run test:electron` 和 `git diff --check` 验证；编辑、删除成功后会关闭弹窗，保存失败会回滚快捷项并保留错误提示。
- **适用边界**：编辑按钮只出现在自定义快捷目录上，固定的六个游戏目录入口不提供编辑或删除操作。

### 快捷目录保存弹窗未关闭修复记录（2026-09-15）

- **背景**：点击快捷目录弹窗的“保存”后出现 `An object could not be cloned.`，导致保存成功分支无法执行，弹窗也不会关闭。
- **根因**：`directoryShortcuts.value` 由 Vue `ref` 管理，读取出来的是响应式 Proxy；它被直接放入 `ipcRenderer.invoke("settings:save", ...)` 的参数，Electron 的结构化克隆不能复制 Proxy。
- **解决方案**：新增 `serializeDirectoryShortcuts()`，在 IPC 边界前将快捷项转换为只包含 `name`、`path` 字符串的普通对象数组；保留弹窗的 `saving` 状态、异常捕获、失败回滚和成功关闭逻辑。
- **验证结果**：通过 `npm run build`、`npm run test:electron` 和 `git diff --check` 验证；保存参数可被 Electron 克隆，成功保存后弹窗关闭，保存失败时快捷项不残留且错误可见。
- **适用边界**：仅影响开始页自定义快捷目录弹窗，不改变固定目录入口、目录打开行为或设置文件结构。

### 开始页目录入口间距收紧（2026-09-15）

- **背景**：目录入口列表在固定高度容器中会拉伸网格行，导致按钮之间出现过大的空白。
- **解决方案**：让列表内容从顶部紧凑排列，并将按钮间距调整为 `5px`。
- **验证结果**：通过 `npm run build` 和 `git diff --check` 验证；目录入口按钮尺寸和打开逻辑保持不变。

### HS2 目录重复选择仍显示无效（2026-09-15）

- **背景**：重新选择实际包含 `HoneySelect2.exe` 的相同 HS2 目录后，开始页仍显示“目录无效”。后端直接校验该目录返回有效，问题只出现在前端状态展示。
- **根因**：`check_game_dir` 任务刚提交时通常处于 `running` 状态，任务数据还没有 `is_valid` 字段；前端把缺失字段按假值处理，提前显示为“目录无效”。此外，轮询只处理正常终态，任务接口异常或任务迟迟不返回终态时会把“检查中”保留到无限期。启动时后端晚于首屏就绪也会跳过第一次目录校验。
- **解决方案**：仅在任务数据明确包含布尔值 `is_valid` 时更新“目录有效/目录无效”；目录切换后先显示“检查中”，并统一通过目录校验函数提交任务。目录校验任务提交缺少任务 ID、轮询接口失败、任务 10 秒内未返回终态或终态缺少 `is_valid` 时，统一显示“检查失败”并记录原因。后端晚到时自动重试健康检查并补做设置、`setup.xml` 和游戏目录校验。
- **验证结果**：通过 `npm run build`、`git diff --check` 和 JavaScript 语法检查；相同有效目录的任务初始状态不会再被误判为无效，最终后端返回有效后显示“目录有效”，没有最终结果时也不会无限停留在“检查中”。
- **适用边界**：只修正目录校验的异步状态同步和后端启动竞态，不改变 HS2 目录判定规则；目录确实不含 `HoneySelect2.exe` 时仍显示“目录无效”。

### 重启后已保存 HS2 目录停留在“检查中”（2026-09-15）

- **背景**：应用重启时后端启动较慢，开始页能够从 `settings.json` 读出已保存目录，但目录状态长期停留在“检查中”，前端任务列表和后端日志中都没有对应的 `check_game_dir` 任务。
- **根因**：首次设置加载在后端未就绪时使用 `loadBackendData: false`，而后端恢复监听触发的 `loadBackendData: true` 请求被 `appSettingsLoadPromise` 直接复用。由于首次加载仍可能在刷新工作台缓存，恢复请求没有机会重新执行，目录校验因此被跳过。
- **解决方案**：将设置加载改为可升级的请求队列：已有无后端加载进行时收到后端加载请求，会在当前加载完成后补执行一次完整加载；启动流程在后端恢复后再检查一次设置状态作为兜底。目录校验提交路径增加实际路径和任务 ID 日志，便于确认前端确实把目录交给后端。
- **验证结果**：后端恢复后会出现 `[Game Dir Check] submit` 和 `[Game Dir Check] task` 日志，`check_game_dir` 最终返回 `is_valid: true` 时开始页显示“目录有效”；后端已在首屏加载完成前恢复的边界情况也会进入完整加载流程。
- **适用边界**：只修复前端设置加载与后端就绪之间的竞态，不修改后端目录识别规则，也不绕过后端校验。

### 工作台扫描阻塞目录校验（2026-09-15）

- **背景**：后端已经显示 ready，但开始页仍保持“检查中”；此时插件状态仍为“待检查”，任务区域也没有目录校验结果。
- **根因**：设置加载在 `applyGameDir()` 后先同步等待工作台工程扫描。工作台扫描通过 Electron 主进程同步读取用户工作空间中的所有工程，目录校验、插件检查和 `setup.xml` 读取都排在它之后；扫描较慢时，目录状态会长时间停留在 `applyGameDir()` 设置的“检查中”。
- **解决方案**：后端可用时，设置加载立即提交 `check_game_dir`；目录校验完成后再执行插件检查、工作台扫描和 `setup.xml` 读取。后端未就绪的首轮设置加载不再等待工作台扫描，避免阻塞后端恢复后的完整加载升级。
- **验证结果**：开始页会先出现 `[Game Dir Check] submit` 和任务 ID，目录校验返回后再进入工作台和游戏配置初始化；工作台扫描耗时不会再阻止 HS2 目录显示有效或无效。
- **适用边界**：只调整前端启动任务顺序，不改变工作台扫描内容和后端 HS2 目录判定规则。

## 启动操作条

页面提供三个启动按钮：

- `开始游戏` → `HoneySelect2.exe`；
- `开始工作室` → `StudioNEOV2.exe`；
- `开始 VR` → `HoneySelect2VR.exe`。

未选择游戏目录或正在读取配置时按钮禁用。启动前如果存在未保存修改，会先保存 `setup.xml`；启动动作通过 preload 的 `launchGameExecutable(launchType, gameDir)` 进入 Electron 主进程。主进程检测 `IPA.exe` 与 `BepInEx\\core`：存在 IPA 时使用 `IPA.exe <target.exe> --launch`，否则直接启动目标 exe；同时检测到 IPA 和 BepInEx 时拒绝启动并写入运行日志。

### 开始页启动按钮移除黑色外边框记录（2026-09-12）

- 背景：截图标注的“开始游戏”“开始工作室”和“开始 VR”按钮仍显示黑色外边框，与顶部栏按钮的轻量化视觉不一致。
- 根因：三个启动按钮继承全局 `button` 的 `2px solid var(--line-strong)` 边框。
- 解决方案：为 `.launch-bar > button` 设置 `border: 0`，保留启动按钮的颜色、文字、禁用状态和启动逻辑。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；三个启动按钮不再显示黑色外边框。
- 适用边界：仅影响开始页启动操作条的三个按钮，不改变 setup.xml 状态徽标、配置控件、目录入口按钮或其它页面按钮。

### 开始页启动按钮改为透明磨砂玻璃记录（2026-09-12）

- 适用边界：仅影响开始页三个启动按钮的背景和边缘质感，不改变启动逻辑、禁用状态、按钮尺寸或 setup.xml 状态徽标。

### 开始页次级启动按钮增强边界与悬停反馈记录（2026-09-12）

- 背景：透明磨砂处理后，“开始工作室”和“开始 VR”按钮的边界与鼠标悬停状态不够明显。

- 适用边界：仅影响开始页“开始工作室”和“开始 VR”按钮，不改变“开始游戏”、setup.xml 状态徽标、配置控件或目录入口按钮。

启动操作条在开始页工作区内与上下相邻容器保持一致的垂直间距：上方工作区内边距和下方内容间距均为 `18px`。该页面专属间距不会改变其它页面的工作区布局。

### 开始页 GitHub 仓库按钮（2026-09-17）

- **背景**：开始页启动操作条右侧存在空白区域，需要提供项目仓库的直接入口。
- **解决方案**：增加右对齐的“GitHub 仓库”玻璃按钮，图标固定在文字左侧且按钮不显示边框；使用 Electron 主进程的 `shell.openExternal` 打开固定地址 `https://github.com/lunaburg/Star_Manager`；渲染进程只暴露无参数的仓库入口，不接受任意外部 URL。
- **样式修正**：仓库按钮使用横向 flex 布局，避免 SVG 块元素将文字挤到下一行；以更具体的启动条选择器覆盖次级启动按钮的细描边，普通、悬停和焦点状态均保持无边框。
- **验证结果**：通过 `npm run build`、Electron/Preload 语法检查和 `git diff --check` 验证；按钮不改变游戏启动按钮、配置徽标或目录入口行为。
- **适用边界**：仅在 Electron 桌面运行时提供外部浏览器入口；仓库地址由应用内置，网络可用性和默认浏览器行为由系统决定。

## 启动器视觉卡和目录入口

中间视觉卡是品牌和启动状态展示区，不承载文件写入操作。右侧目录入口使用当前游戏根目录拼接相对路径：

| 文案 | 相对路径 |
| --- | --- |

## 当前持久化边界

游戏目录和输入/输出目录等管理器设置通过 Electron `settings.json` 保存，详见[设置页布局](settings-layout.md)。HS2 游戏配置单独保存在游戏目录的 `UserData/setup.xml`，不写入管理器自身的 `settings.json`。

桌面能力使用：

## 空状态和错误状态

- 未选择游戏目录：保留页面结构，禁用启动按钮和目录入口。
- 目录校验失败：顶部显示目录无效，依赖游戏目录的浏览和任务操作由主壳层禁用。
- 启动文件不存在或启动失败：保持页面可用，并在运行日志中显示错误。
- `setup.xml` 解析错误：显示错误摘要，阻止写回源文件并禁用启动按钮。
- `setup.xml` 保存错误：保留 dirty 状态，阻止启动，直到用户修复或重新选择目录。
- 注册表同步失败：XML 仍会保留已生成的备份和新配置，但页面显示警告，便于用户处理权限或系统问题。

### Star Manager 插件自动安装（2026-09-15）

- **背景**：人物卡读取、运行时换装和读取审计依赖 `StarManager.CardMetadata`、`StarManager.GameItemProbe` 和 `StarManager.CharacterCardReadProbe` 三个 BepInEx 插件；更换游戏目录后，用户不应再手动复制插件。
- **解决方案**：发行包将三个 DLL 放在 `resources/StarManager/`。Electron 主进程在选择游戏目录以及启动时恢复已保存目录后，检查 `BepInEx/Plugins/`；缺失的同名 DLL 通过管理器原子复制安装，已有 DLL、`.dll.dl_` 和历史 `.dll.disabled` 文件不覆盖、不重新启用。
- **验证结果**：插件安装逻辑通过 Electron 单元测试；发行输入检查会在 `package:win` 前验证三个 DLL 均存在；前端生产构建与 `git diff --check` 作为交付检查。
- **适用边界**：只安装这三个 Star Manager DLL，不负责安装 BepInEx 框架或其他第三方插件；目标目录必须是包含 `HoneySelect2.exe` 的 HS2 根目录，文件权限不足时会保留目录选择并将错误写入运行日志。

### 开始页固定插件设置（2026-09-16）

- **背景**：启动器需要在截图红框对应的开始页配置区域直接管理 SplashScreen、GraphicsMod、DHH、自动保存、更好的抗锯齿和 PoVX，避免用户切换到插件库存页逐项查找。
- **解决方案**：开始页读取 `GET /plugins/status` 并按固定相对路径显示六个紧凑开关；启用/禁用复用 `POST /plugins/toggle`。插件不存在时显示“未安装”并禁用开关；状态变化直接反映在开关状态，插件通常需要重启游戏后生效。
- **后缀规则**：新的禁用操作统一将 `Example.dll` 重命名为 `Example.dl_`；历史 `.dll.disabled` 文件仅兼容读取，重新执行禁用时迁移为 `.dl_`。
- **适用边界**：六个 DLL 开关只管理文件名状态，不编辑插件配置、不执行 DLL，也不保证插件自身配置项可用；控制台和实验模式由下方专门的文件配置/Modpack 操作负责。

### 开始页控制台与实验模式设置（2026-09-16）

- **激活控制台**：读写 `BepInEx/config/BepInEx.cfg` 的 `[Logging.Console]` 区段，仅修改 `Enabled = true/false`。
- **实验模式**：开启时创建 `BepInEx/LauncherEN/ilikebleeding.txt`，并将 `mods/Sideloader Modpack - Bleeding Edge` 移至 `mods.experimental/`；关闭时反向移动并删除标记文件。
- **安全边界**：移动前检查源/目标冲突；不会覆盖已有目录，不会删除 Modpack 内容；配置写入采用临时文件替换。
