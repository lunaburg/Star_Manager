# Zipmod 库布局

## 目标

Zipmod 库通过本地索引浏览、诊断和整理所选 HS2 游戏目录中的 `mods/**/*.zipmod`。

这个页面不是普通文件列表，而是面向大资源库的本地模组管理工作台。默认体验应优先支持快速扫读、错误定位、重复 GUID 处理和安全整理。

真实数据仍然来自文件系统、`manifest.xml` 和 CSV。前端读取后端索引中的 `zipmods` 主表，并在选中模组时展示关联的 `mod_items`、解析诊断和文件位置。

## 信息来源

### `zipmods`

模组级主索引，来自 `manifest.xml` 和 zipmod 文件属性。

推荐用于列表和详情的字段：

- `id`：数据库 ID。
- `guid`：manifest GUID，业务定位优先使用它。
- `name`：mod 名称。
- `author`：作者。
- `version`：版本。
- `item_count`：该 zipmod 中解析出的物品总数。
- `scan_status`：`ok`、`missing_manifest`、`invalid_manifest`、`read_error`、`stale`。
- `scan_error`：扫描错误原因。
- `unity3d_status`：`in_mod`、`not_in_mod`、`missing`、`error` 或空值。
- `unity3d_source`：`game_abdata` 或 `other_zipmod`，用于说明不在当前 zipmod 内的资源来源。
- `unity3d_not_in_mod_count`、`unity3d_in_mod_count`、`unity3d_in_game_count`、`unity3d_other_mod_count`、`unity3d_missing_count`：资源状态汇总。
- `duplicate_zipmod_count`：同 GUID 重复文件数量。
- `file_name`：zipmod 文件名。
- `relative_path`：相对 `mods/` 的路径。
- `file_path`：完整路径。
- `last_scanned_at`：最近扫描时间。

### `mod_items`

物品级索引，来自 zipmod 或解包目录内的 `abdata/list/**/*.csv`。

选中 zipmod 后可展示：

- `item_id`：CSV 中的 `ID`。
- `name`：游戏内物品名。
- `kind`：物品类别数字，展示时映射为中文分类。
- `csv_path`：来源 CSV。
- `thumbnail_cache_path`：缩略图缓存路径。
- `thumbnail_status`：`ready`、`missing`、`error`。
- `unity3d_status`：物品引用的 `.unity3d` 是否在 zipmod 内、游戏目录中、缺失或不可用。
- `parse_status`：`ok`、`missing_header`、`short_row`、`parse_error`。

## 浏览模式

模组管理页必须支持两种浏览模式：

- 模组浏览：默认模式，以 `zipmods` 为主表，帮助用户按 zipmod 包处理状态、路径和诊断。
- 物品浏览：以 `mod_items` 为主表，帮助用户按游戏内物品查找来源模组。

浏览类型使用顶部 segmented control：

```text
[物品浏览] [模组浏览]
```

浏览类型 tab 与详情抽屉 tab 使用同一套经典页签样式：淡蓝和浅粉渐变、顶部圆角、细描边、底部基线；当前项像抬起的标签页，使用白底和深色细描边标识。

浏览类型行右侧放人物卡依赖筛选滚轮，用于按角色卡依赖关系筛选当前浏览模式，选项为 `已使用`、`未使用`、`全部`。该控件必须可横向滚动，避免挤压浏览类型 tab；不在这里放刷新列表按钮，避免和数据库重建、筛选变化触发的刷新行为重复。若后续确实需要导出清单等低频操作，可放置轻量图标按钮，并提供 `title` / `aria-label`，避免和下方筛选工具栏混在一起。

切换浏览类型时必须同步切换：

- 左侧筛选控件。
- 主表格列。
- 当前选中记录。
- 右侧详情抽屉的标题、状态 badge、内容结构，以及详情 tab 内的操作入口。

物品浏览选中的是 `mod_items` 记录，详情抽屉显示物品信息和来源模组。模组浏览选中的是 `zipmods` 记录，详情抽屉显示模组信息、关联物品和诊断信息。列表不会默认选中第一行；未选中对象时详情抽屉显示“请选择一个对象”。

文件定位类操作跟随对应记录展示。模组详情的“文件名”信息栏本身就是可点击控件，不显示路径文本；点击后通过 Electron `shell.showItemInFolder` 打开资源管理器并选中对应 `.zipmod` 文件。

## 总体布局

模组管理页使用“资源库表格 + 常驻同步详情抽屉”的双栏布局：

```text
+------------------------------------------------------+----------------------+
| 模组管理                                             | 同步详情抽屉          |
| 8,214 zipmod · 142,309 items · 17 errors · 6 dupes   | 当前选中记录          |
| [物品浏览] [模组浏览]                                | 物品详情或模组详情     |
| [按当前模式显示筛选项]              [排序] [扫描]     | 基础信息              |
|------------------------------------------------------| 文件位置              |
| 当前模式表格                                         | 解析诊断              |
| ...                                                  | 详情 tab 内操作        |
+------------------------------------------------------+----------------------+
```

左侧主区域服务于大批量扫读和筛选。右侧详情抽屉保持打开，随浏览模式和选中行更新，避免频繁弹窗打断浏览。

模组管理页面由应用壳层的 `KeepAlive` 保留页面实例。实际列表滚动容器由 `ModsView` 注册到 `App.vue`，应用壳层在切页前同步捕获其 `scrollTop`，返回后按当前浏览模式恢复；因此返回模组管理时会保留列表滚动位置、当前筛选、浏览模式和选中对象。离开页面不会因页面实例停用而丢失滚动状态。

### 导航返回保留列表位置（2026-09-05）

- 背景：用户从卡片管理返回模组管理后，列表滚动条会回到顶部，之前的浏览定位需要重新寻找。
- 根因：滚动位置只在模组页自身的激活、停用和卸载钩子中处理，页面切换时这些钩子的时序不稳定；列表异步更新也可能在恢复后把 `.table-wrap` 的位置重新变为顶部。
- 解决方案：页面继续通过应用壳层的 `KeepAlive` 保留已访问页面实例；`ModsView` 将实际 `.table-wrap` 注册给 `App.vue`，由应用壳层在 `activeView` 同步变化时捕获滚动位置，并在返回、浏览模式切换和列表异步加载后按 `mods` / `items` 分别恢复。位置只保存在当前 renderer 进程内，不写入 `localStorage`，因此应用重启后会重新从顶部开始，不再依赖重复挂载模组异步组件。
- 验证结果：`npm run build` 通过；`git diff --check` 通过；已核对模板中模组管理实例在导航切换时保持挂载。
- 适用边界：位置只在当前应用运行期间按模组浏览和物品浏览分别保存；刷新页面或重启应用后不保留滚动位置，筛选条件和浏览模式的原有初始化规则不变。

详情抽屉建议宽度为 `380-420px`。模组浏览使用表格作为主视图。物品浏览支持表格与紧凑缩略图网格切换：表格用于精确扫读，紧凑视图用于按外观快速浏览；切换偏好保存在本机。两种物品视图共用筛选、选中状态、详情抽屉、双击定位来源模组和滚动增量加载。

- 背景：详情面板已经接入透明磨砂背景，但物品摘要、详情页签、信息栏、链接和工具按钮仍使用不透明白底或较硬的边界，与面板背景之间出现割裂。

### 物品浏览筛选

物品浏览工具栏显示四类检索入口，Kind/类别筛选位于全局顶部栏：

- 来源：按“全部来源”“模组物品”或“游戏本体”筛选。默认显示两类来源；游戏本体记录来自当前所选 HS2 目录对应的 `builtin_items`。
- 作者：按 `mod_items.zipmod_author` 或来源 `zipmods.author` 筛选。
- 状态：当前支持 `ready`、`error`、`thumb`，分别对应可展示、解析/主资源异常、主资源可用但缩略图缺失或错误。
- 搜索物品名字：按 `mod_items.name`、`item_id` 或 `zipmod_guid` 搜索。

物品浏览工具栏应使用稳定网格布局：搜索框占较大宽度，来源、作者、状态三个筛选控件使用较窄且一致的宽度。其中作者控件支持输入关键字联想并选择作者。全局顶部栏中的 Kind 筛选按固定分区与一级类别组织：男性和女性各显示面部、身体、服饰、姿势，通用显示头发、饰品，其它显示地图、图案；头发与饰品只在通用组显示，男女共享同一组 Kind。男性、女性和通用组的多 Kind 一级类别只打开对应的二级子类界面，不把该类别下的多个 Kind 一起送入查询；地图和图案没有二级分类，点击一级按钮直接应用对应筛选。所有具体筛选一次只设置一个 `itemFilters.kind`，左侧“全部 Kind”清除筛选；地图筛选仍通过现有“地图”筛选项同时匹配工作室、本体和双端地图。所有控件必须设置 `min-width: 0` 或等效约束，避免筛选控件撑出父容器。

### 模组浏览筛选

- 作者：按 `zipmods.author` 筛选，输入内容使用不区分大小写的包含匹配；输入作者前缀即可筛出对应作者的多个模组。

## 物品表格

物品浏览推荐表格列：

- 状态。
- 缩略图。
- 物品名。
- Kind。
- 作者。
- 来源模组。

展示规则：

- 缩略图列放在物品名之前，沿用现有缩略图缓存和显示尺寸或稳定占位图；本次性能优化不新增小尺寸缩略图、不压缩或替换原始缩略图资源。表格缩略图不使用黑色描边，避免和按钮/卡片控件混淆。
- 标准密度下物品列表行高建议不低于 `60px`，表格缩略图建议为 `46px` 固定尺寸，并保留至少 `6px` 上下内边距，确保图片不触碰行的上下边界。
- 物品名是主要扫读字段，列宽应优先保证。
- Kind 展示中文映射，同时保留原始数字可放 tooltip 或详情抽屉。
- 作者来自来源 zipmod；游戏本体物品的作者和来源显示为“游戏本体”。
- 模组来源可点击或双击切到模组浏览并选中对应 zipmod；游戏本体物品没有来源模组跳转。
- `thumbnail_status` 和 `parse_status` 以 badge 显示。
- `thumbnail_status = ready` 时显示缓存缩略图；`missing` 或 `error` 时显示带文字的占位图，不让行高跳动。

当前加载策略：

- 进入物品浏览时先调用 `GET /mods/database`。
- 数据库不存在时不加载表格，提示创建数据库。
- 数据库存在时首批调用 `GET /mods/items?offset=0&limit=96&source=all&game_dir=...&include_total=1`，只读取当前所选 HS2 目录的原版记录。
- 表格或紧凑视图滚动接近底部后继续按 96 条加载；后续请求使用 `include_total=0`，只通过多取一条记录判断 `has_more`，不重复执行全量总数统计。
- Kind 数字在前端映射为中文类别，例如 `351` 显示为 `饰品 mod / 头部`；模组物品的未知 Kind 保留原始值，游戏本体物品的未知 Kind 不进入浏览列表。
- 原版物品复用已提取的缩略图缓存，不修改游戏本体；数据库没有对应当前游戏目录的原版索引时，列表仍可显示模组物品。

### 缩略图加载性能

物品库可能包含数万条记录，首屏只需要视口附近的少量行和缩略图。当前实现的性能策略如下：

- 首批及后续物品请求限制为 96 条，避免一次性创建过多 Vue 节点、图片组件和观察器；继续滚动时仍按增量批次读取，不改变完整库的可浏览范围。
- 表格视图和紧凑网格视图都使用虚拟列表/虚拟网格，只渲染视口附近的行（含少量 overscan），已加载数据不会全部持续挂载到 DOM；原有状态、选中、双击定位、右键菜单和装配模式交互保持不变。
- 物品列表在距离滚动底部约 480px 时提前请求下一批，让数据库查询和响应处理尽量与用户浏览最后一段内容并行；模组列表继续使用原有的 160px 触底阈值。
- `LazyThumbnail` 使用共享 `IntersectionObserver`，并绑定到实际的物品列表滚动容器；距离视口约 360px 内才开始请求图片。前 24 条图片使用较高优先级，远处图片保持懒加载。
- 后端的缩略图磁盘缓存、缓存接口、`Cache-Control` 和 ETag 策略保持不变；本次优化不生成小尺寸缩略图，不改变缩略图文件内容、清晰度或现有 URL。

### 触底增量加载性能优化（2026-08-29）

- 背景：物品浏览下滑至底端加载新一批数据时，页面曾出现约 2–3 秒无响应，尤其在已经加载较多记录后更明显。
- 根因：分页请求每次都重复执行全量 `COUNT(*)`；前端每批追加记录后，表格和紧凑网格会持续保留所有历史节点，并为不可见物品创建缩略图组件和观察器，造成 Vue 更新、布局、绘制和图片请求集中发生。
- 解决方案：将物品批次调整为 96 条；首批保留总数统计，后续页通过 `limit + 1` 判断 `has_more` 并跳过重复统计；物品表格和紧凑网格均改为视口附近虚拟渲染；为名称排序补充不区分大小写的 SQLite 索引。缩略图仍复用原缓存和原 URL，不引入小尺寸缩略图。
- 验证结果：`apps/backend/tests/test_mod_database_queries.py` 的 13 项测试全部通过，`npm run build` 生产构建通过；新增分页测试验证后续页返回 `total = null` 且正确报告 `has_more`。
- 适用边界：本次虚拟化仅覆盖物品浏览的表格和紧凑视图，模组浏览表格仍使用原有分页渲染；数据库查询仍使用 offset 分页，超大偏移量的进一步优化可改用稳定游标分页。若原始缩略图文件本身很大，网络/磁盘读取耗时仍可能存在，但不会由前端一次性挂载全部记录放大。

验证方式：使用 `npm run build` 检查 Vue 模板、CSS 和生产构建，并运行物品查询单元测试；在物品浏览的表格、紧凑网格、筛选重载和滚动增量加载路径中确认缩略图仍能正常显示。适用范围仅为物品浏览列表，不改变缩略图提取、数据库建库和详情抽屉中的原有资源流程。

装配模式下不依赖右键菜单：点击右侧角色栏位后，左侧会自动按该栏位的 `CategoryNo` 筛选；表格和紧凑缩略图视图中的物品均可通过鼠标左键直接穿戴到已选栏位。左键换装会沿用当前栏位的类型约束，服装直接使用类别对应栏位，头发使用固定的 `hairSlotNo`，面部使用当前栏位类别，美瞳/瞳孔使用当前栏位的眼别 `facePartNo`，身体使用当前栏位类别，身体彩绘使用当前栏位的 `bodyPartNo`，配饰使用当前栏位的 `partIndex` 作为角色 `slotNo`。装配模式下双击不再定位来源模组，避免与直接换装操作混淆。

换装链路为：

```text
mod_items.kind + item_id + zipmod_guid
  或 builtin_items.category_no + item_id
  -> POST /game-item-probe/apply
  -> StarManager.GameItemProbe 主线程调用游戏原生换装方法
  -> 轮询 /game-item-probe/command
```

边界必须在界面中明确：

- 只改变当前角色制作器中的角色，不写入物品库、zipmod、CSV 或角色卡。
- 探针端口不验证游戏目录；使用前需确认正在运行并占用探针端口的 HS2 与 Star Manager 当前选择的游戏目录一致。
- 模组物品的 `item_id` 被作为 CSV 原始 `slot`，不能直接当作游戏 `localSlot`；原版物品的 `item_id` 是原版列表 ID，直接作为 `localSlot`，两条路径都由插件再次校验类别和列表项是否存在。
- 映射冲突、游戏未进入角色制作器、插件未运行、游戏列表找不到物品或命令超时都显示明确错误，不按名称猜测或自动选择候选。
- 身体以外的姿势、地图和其它未被插件支持的 Kind 保持不可换装；普通模式右键菜单或装配模式左键尝试时会显示不支持原因。面部开放脸型、肌肤/细节、胡子、眉毛、睫毛、眼影、美瞳、瞳孔、眼睛高光、腮红、口红和痣/雀斑；`317/318` 眼睛类别必须绑定左眼或右眼。身体开放肌肤、细节、晒痕、身体彩绘、乳头和阴毛，`8/313` 必须绑定 `bodyPartNo`。头发仅开放结构发类别 `300`–`303`，`305` 发色预设和 `306` 发网格/发型选项仍不可直接换装，且开放的四类只能使用类别对应的 `hairSlotNo`。
- 命令成功表示游戏原生换装调用已接受，贴图和模组资源仍可能异步加载，界面会提示这一点。

问题背景与验证：此前物品浏览只连接本地数据库和资源预览，未有游戏侧写入入口。当前实现通过后端的固定回环代理接入已有 `StarManager.GameItemProbe`，不暴露任意转发接口；使用 `npm run build`、插件构建和 `backend/tests/test_game_item_probe.py` 验证。头发类别/栏位映射已通过当前 HS2 程序集确认，但新插件 DLL 尚未安装重启进行头发实机调用；服饰此前已有实机验证，不能替代头发验证。

### 装配模式

物品浏览工具栏的物品/模组页签之间提供“装配模式”切换。开启后，左侧仍保留物品浏览和筛选，右侧详情抽屉改为显示当前 HS2 角色制作器的实际状态，不再依赖左侧是否选中某个物品；退出后恢复普通的物品详情抽屉。装配模式下 Kind 筛选控件会被禁用，进入模式时清除原有 Kind 条件；点击右侧具体角色栏位后，以该栏位的 `CategoryNo` 自动筛选左侧可装配物品，点击栏位后使用高亮背景和边框表示当前筛选目标，退出装配模式后恢复 Kind 控件。五个大类使用互斥折叠面板，默认展开服装栏位；点击当前大类可收起，点击另一个大类会自动收起前一个并展开新的大类，同一时间最多展示一个大类下的小类栏位。

装配模式通过 `GET /game-item-probe/current` 读取并每秒轻量刷新一次当前角色状态，右侧按以下五组展示栏位：

装配模式顶部的实时卡片显示“角色编辑器”或“H 场景角色”、角色选择器和连接状态，不显示 LIVE 标记、人物姓名、坐标或角色文件名。

装配模式的连接徽标在后台每秒刷新角色装配数据时保持稳定，不随静默轮询短暂切换为“同步中”；“同步中”只用于首次读取或用户手动重试。这样可以保留实时同步，又避免连接状态闪烁。

## Zipmod 表格

模组浏览推荐表格列：

- 状态。
- 名称。
- 作者。
- 版本。
- 物品数。
- 相对路径。
- GUID。
- 最近扫描。

展示规则：

- `scan_status = ok` 显示绿色或普通 `正常` badge。
- `missing_manifest`、`invalid_manifest`、`read_error` 显示琥珀或红色诊断 badge。
- `stale` 显示灰色 `已失效` badge。
- 重复 GUID 显示 `重复 GUID` badge，即使主记录本身可解析。
- GUID、路径和错误码使用等宽字体。
- GUID 在表格中可截断，详情抽屉显示完整值。
- 当前选中行使用浅粉或浅蓝背景，不增加额外粗边框。
- `item_count = 0` 不一定是错误，但应在详情诊断中说明可能原因。

表格交互：

- 单击行后选中该对象并更新右侧详情抽屉。
- 未选中对象时，右侧详情抽屉只显示“请选择一个对象”。
- 双击物品行可定位来源模组。
- 双击模组行可进入详情抽屉的 `物品` tab 或展开关联物品。
- 点击状态 badge 可筛选同类状态。
- 文件路径不在表格内展示。模组详情中的“所在文件夹”信息栏用于打开资源管理器并选中 zipmod 文件。

## 数据加载

模组管理页依赖本地 SQLite 索引，不直接扫描文件系统列表。

当前接口：

```text
GET /mods/database
GET /mods/zipmods?offset=0&limit=200&author=&status=&usage=
GET /mods/zipmods/authors
GET /mods/zipmods/<id>/manifest
GET /mods/zipmods/<id>/diagnostics
GET /mods/items?offset=0&limit=240&search=&kind=&author=&status=&usage=&source=all&game_dir=<encoded_game_dir>
GET /mods/items?zipmod_id=<zipmod_id>&offset=0&limit=1000
GET /mods/items/filters?game_dir=<encoded_game_dir>
GET /mods/thumbnails?path=<encoded_thumbnail_cache_path>
GET /mods/models/<file.glb>
GET /mods/mannequin/body.fbx
GET /game-item-probe/status
GET /game-item-probe/current
GET /game-item-probe/command?id=<command_id>
POST /game-item-probe/apply
```

加载规则：

- 进入模组浏览或物品浏览前先检查数据库。
- 数据库不存在时不加载列表，提示创建数据库。
- 模组浏览首批 200 条，滚动到底部附近继续加载。
- 物品浏览首批 240 条，滚动到底部附近继续加载。
- 模组详情的物品 tab 按当前 `zipmods.id` 查询关联物品。
- 缩略图通过后端缩略图接口加载，前端不直接读取本地文件路径。
- 筛选项来自 `/mods/zipmods/authors` 和 `/mods/items/filters?game_dir=<encoded_game_dir>`；原版 Kind 和“游戏本体”作者只来自当前游戏目录，空作者在前端展示为 `未知作者`。

- 适用边界：仅调整物品详情“工具”页签的前端呈现，不改变工具调用、缩略图写回、删除确认或后端接口行为。

### 模组详情

分组展示：

- 标题区：mod 名称、作者、版本、状态 badge。
- 基础信息：数据库 ID、完整 GUID、物品数、最近扫描时间。
- 文件位置：文件名信息栏即打开目录入口。
- 当前实现中详情信息栏使用紧凑布局，值紧跟标题显示，以便展示更多 GUID、文件名和时间信息。文件名栏不显示路径，整条信息栏作为打开目录并选中当前 `.zipmod` 文件的入口。

### 模组详情容器移除黑色边框记录（2026-09-11）

- 背景：模组管理右侧详细信息容器的外层黑色边框过重，与页面工作区背景衔接不自然。
- 根因：`.mod-detail-panel` 同时使用共享 `.panel` 样式，继承了 `3px` 黑色边框。
- 解决方案：在 `.mod-detail-panel` 专属规则中将 `border` 设置为 `0`；标题栏、详情分组和内部控件的边框保持原有样式。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证。
- 适用边界：仅移除模组管理右侧详细信息容器的外层边框，不改变详情内容、文件定位入口、物品 tab 或诊断操作。

### 模组文件定位入口合并（2026-09-05）

- 背景：模组详情的“文件位置”区域同时显示“文件名”和“所在文件夹”两行，用户需要点击第二行才能定位文件，信息重复且入口不直观。
- 根因：文件名仅作为静态信息展示，定位动作单独放在另一个空值行中；现有 Electron `showItemInFolder(filePath)` 能力已经支持打开目录并选中文件，无需新增接口。
- 解决方案：将两行合并为一个“文件名”信息栏，整栏作为按钮，点击后继续调用 `showItemInFolder`，直接在资源管理器中打开模组所在目录并选中对应 `.zipmod` 文件；文件名过长时使用省略号，悬停和无障碍标签保留完整定位语义。
- 验证结果：已完成前端源码补丁，`npm run build` 和 `git diff --check` 均通过；模板、样式和 Electron 桥接调用保持一致。
- 适用边界：仅定位当前选中的模组文件，不修改文件、数据库或 zipmod 内容；没有有效 `file_path` 时沿用现有错误日志行为。

### 作者筛选下拉层级修复（2026-09-13）

- 背景：模组浏览工具栏中的作者联想列表向下展开时，列表下半部分被后方表格表头和首行遮挡，无法完整选择作者。
- 根因：工具栏使用 `backdrop-filter` 形成独立层叠上下文；作者列表自身的 `z-index` 只能在工具栏上下文内生效，而工具栏整体仍按文档顺序绘制在后方表格之前的低层级。另一个问题是，模组列表已加载时数据库加载函数会提前返回，可能跳过作者选项请求，导致前端只显示固定追加的“全部作者”和“未知作者”。
- 解决方案：为模组页直接子级工具栏设置相对定位和高于表格的层级，使作者下拉列表连同其磨砂表面在表格上方绘制；当列表已经加载时也补充作者选项请求，并在作者筛选获得焦点或点击展开时再次确保作者数据已加载；不改变表格滚动容器、筛选查询或失焦关闭逻辑。
- 验证结果：前端生产构建通过，`git diff --check` 未发现空白错误。
- 适用边界：仅修复模组浏览和物品浏览工具栏作者下拉列表与后方列表的层叠关系，不改变筛选选项、数据查询或其它下拉控件行为。

### 模组管理列表滚动位置保持（2026-09-16）

- 背景：从模组管理页切换到开始游戏等其它页面后再返回，模组或物品列表的滚动位置会回到顶部，用户需要重新寻找刚才浏览的位置。
- 根因：列表滚动位置存放在 `.table-wrap` 的 DOM `scrollTop` 中，之前由 `ModsView` 自身的生命周期保存和恢复，跨页面切换时可能错过父层更新顺序；模组列表与物品列表也共用同一个滚动容器。
- 解决方案：在 `App.vue` 中按“模组浏览”和“物品浏览”分别记录 `scrollTop`，仅保存在当前 renderer 进程内；`ModsView` 只注册 `.table-wrap` 并上报滚动事件，应用视图切换时由父层同步捕获，返回、浏览模式切换和列表数据异步加载完成后的多个时机由父层恢复。两种浏览模式已经加载的行数据、分页偏移、`hasMore` 和进行中的首批/增量请求继续由 `App.vue` 持有，返回页面时不会重新清空或重置分页。页面实例由应用壳层的 `KeepAlive` 管理，不额外重复挂载模组异步组件；应用重启后内存清空，滚动位置回到顶部。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；筛选、分页加载、详情选择和两种列表视图不改变；返回物品浏览时保留已加载批次和继续加载状态。
- 适用边界：仅保持模组管理列表的垂直滚动位置，不写入后端或游戏目录；横向滚动、详情抽屉内部滚动和数据库内容变化不在本次范围内。

高风险整理操作不放在详情抽屉内。后续如重新加入移动、删除或在原目录整理，必须走独立高风险确认流程。

### 模组物品 tab

展示选中 zipmod 的 `mod_items` 摘要。当前实现使用：

```text
缩略图 | 物品名 | Kind 分类 | 状态
```

缩略图规则：

- `thumbnail_status = ready` 显示缓存图。
- `missing` 或 `error` 显示稳定占位图。
- 失败原因放到诊断 tab 或 tooltip，不阻塞物品列表。
- 模组物品 tab 只展示关联物品信息，不显示重新扫描、打开目录、复制 GUID、整理、删除等操作控件。
- 关联物品列表不显示 item ID，副信息只显示 Kind 中文分类，避免类别被截断。

### 诊断 tab

展示：

- `scan_status` 和 `scan_error`。
- CSV 解析状态摘要。
- 缩略图提取状态摘要。
- 重复 GUID 信息。
- stale 记录说明。
- 当前实现中诊断 tab 也承载对应的修复动作：补作者、选择缩略图、清理重复模组、补入 zipmod，以及在满足后端条件时删除模组。
- Unity3D 诊断为“不在当前 zipmod 内”时，显示统一标题；若来源为游戏目录，显示 `game_path` 并允许“补入 zipmod”；若来源为其它 zipmod，显示提供者文件名和完整路径提示，不显示补入按钮。

如果存在重复 GUID，必须展示主记录和重复文件：

```text
主记录：mods/Sideloader/roy12/aiko.zipmod
重复文件：
- mods/_old/roy12/aiko.zipmod · 1.2.0 · 48 MB · 2025-12-09
- mods/downloads/aiko.zipmod · 1.3.0 · 51 MB · 2026-01-03
```

重复文件不应被静默忽略，也不应直接合并到主记录的 `mod_items`。
## 风险操作

安全默认模式为 `Copy`。任何会修改游戏目录的操作都必须进入高风险确认流程，包括：

- 移动 zipmod。
- 删除 zipmod 或重复文件。
- 在原目录整理文件。
- 批量改名。

高风险确认必须展示：

- 将要改变什么。
- 影响文件数。
- 源路径和目标路径。
- 是否可逆。
- 更安全的替代操作。
- 具体确认按钮文案。

按钮文案示例：

```text
确认移动 12 个 zipmod
确认删除 3 个重复 zipmod
确认整理游戏目录中的文件
```

不要使用 `OK`、`Yes`、`确定` 这类泛化确认文案。

## 空状态

空状态必须具体：

- 未选择 HS2 目录：展示目录选择入口和预期目录结构。
- 未建立索引：展示扫描 `mods/**/*.zipmod` 的操作。
- 搜索无结果：显示当前搜索词和清除筛选操作。
- 后端不可用：禁用后端操作，显示重试入口。
- 选中 zipmod 但无物品：说明可能是无 CSV、CSV 解析失败或该 zipmod 不是物品类模组。
