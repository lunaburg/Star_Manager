# 运行日志布局

## 当前职责

运行日志是一个完整工作区页面，用于查看前端本地记录的启动、后端健康检查、路径选择、任务提交、任务进度、完成和失败消息。它不是后端持久化日志，也不替代模组/角色卡详情中的诊断信息。

## 当前布局

```text
+--------------------------------------------------+
| 运行日志                                      X   |
+--------------------------------------------------+
| [清空显示] [复制全部] [导出日志(禁用)] [级别] [搜索] |
+--------------------------------------------------+
|                                                  |
|  Ready.                                          |
|  [Mode] zipmod extract mode: Copy               |
|  [Backend] Python backend is ready.              |
|                                                  |
+--------------------------------------------------+
```

主体使用深色终端区域和等宽字体；日志由 `ctx.logs` 数组按顺序渲染。关闭按钮当前把 `activeView` 设置为 `overview`。

## 当前交互和占位行为

- **清空显示**：清空当前 Vue 日志数组和已见任务消息，不删除后端任务状态或数据库。
- **复制全部**：当前只记录 `[Clipboard] copy placeholder`，尚未接入系统剪贴板。
- **导出日志**：当前按钮禁用。
- **级别下拉框和搜索框**：当前页面展示控件，但没有连接筛选逻辑；输入不会改变 `logs` 显示。
- **自动滚动**：当前没有实现独立开关。

因此文档和 UI 不应把“日志导出、持久化筛选、自动滚动”描述成已完成能力。

## 日志内容

当前常见消息包括：

- `Ready.`、zipmod 提取模式和后端启动状态；
- 选择游戏目录和目录校验结果；
- `Task submitted: <task_type>`；
- 轮询得到的任务消息、进度和错误；
- 数据库变动检测、自动增量重建、导入/整理/导出结果；
- 直接 HTTP 操作失败或文件定位失败。

任务完整状态仍通过 `GET /tasks/:task_id` 获取，前端轮询后把新消息追加到本地数组。

## 相关接口和代码

运行日志当前不请求独立日志 API，依赖：

```text
GET /health
POST /tasks
GET /tasks/:task_id
```

未来如果需要跨重启保存日志，可另行设计日志存储和 `GET /logs`；不能把前端数组直接当作稳定的后端接口契约。

- `apps/src/components/views/LogsView.vue`
- `apps/src/App.vue`：`log()`、任务轮询、`clearLogs()`
- `apps/backend/app/bridge.py`：任务消息和状态
