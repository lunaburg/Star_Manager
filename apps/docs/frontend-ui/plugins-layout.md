# 插件管理布局

## 目标

插件管理用于浏览所选 HS2 游戏目录中的 BepInEx 插件程序集，帮助用户确认插件身份、版本、依赖和解析异常。它不执行 DLL；启用/禁用单个插件时只会安全地重命名对应 DLL，不会删除或覆盖插件内容。

## 当前页面

页面入口是左侧“插件管理”，使用“插件列表 + 右侧详情”双栏结构：

- 插件管理页不显示全局顶部栏，工作区回收其布局高度；目录、任务、Backend 状态和重建数据库仍可在其他页面使用。
- 页面最外层容器不显示通用面板的黑色外框；插件列表与右侧详情区域仍保留各自的内部边界，维持双栏工作区的清晰分隔。
- 插件管理工作区回收顶部空白，页面标题从工作区顶部开始显示；该间距调整仅作用于插件管理页。
- 工具栏提供名称/GUID/DLL 搜索和“打开 BepInEx 目录”。
- 首次进入页面或游戏目录变化时自动扫描；当前界面没有独立的强制重扫按钮。
- 列表显示插件名、版本、类型和状态；前端会保留当前选中项。
- 详情显示相对路径、功能说明、插件 GUID/版本、BepInEx 依赖、适用进程和解析诊断，并提供单个插件的启用/禁用按钮。
- 启用/禁用操作需要确认，完成后直接更新当前行，不重新解析全部 DLL；禁用状态使用替换 `.dll` 后缀得到的 `.dl_` 文件名表示（如 `Example.dl_`），游戏重启后生效。历史 `.dll.disabled` 文件仍可读取，但新的禁用操作一律使用 `.dl_`。禁用插件仍保留在列表中，便于再次启用。下一次主动扫描时，文件指纹会自动识别外部变化。
- 空状态区分未选择游戏目录、准备扫描、没有匹配结果和扫描失败。

### 插件管理页面控件玻璃化记录（2026-09-12）

- 背景：插件管理页面的搜索、打开目录、插件列表、状态按钮、详情区域和启停确认弹窗混用实体白色块、深色硬边与不透明语义色，和应用的透明磨砂玻璃方向不一致。
- 解决方案：在插件管理页面作用域内统一使用半透明背景、低对比边缘、背景模糊和轻阴影；搜索框、目录按钮、状态按钮、诊断标签、详情说明、进程标签及确认弹窗保留启用/禁用、选中、错误和键盘焦点语义。
- 验证结果：通过 `npm run build` 与 `git diff --check` 验证；插件扫描、筛选、详情查看和单插件启停逻辑不变。
- 适用边界：仅影响插件管理页面及其启停确认弹窗的视觉控件，不改变插件扫描范围、缓存、文件重命名规则或其他页面样式。

### 插件管理搜索栏背景与边界统一记录（2026-09-12）

- 背景：搜索栏外层继承通用工具栏的浅色背景和底部边界，与标题区域及下方插件浏览区的连续背景不一致。
- 解决方案：仅在插件管理页面将搜索栏外层背景设为透明，并移除顶部、底部边界及阴影；保留原有外层高度、内边距以及搜索框和目录按钮的玻璃控件样式。
- 验证结果：通过 `npm run build` 与 `git diff --check` 验证；搜索、目录打开和插件扫描逻辑不变。
- 适用边界：仅影响插件管理页面搜索栏外层，不改变其他页面通用工具栏或搜索控件样式。

### 插件管理标题与搜索栏之间移除横线记录（2026-09-12）

- 背景：插件页标题继承通用模块标题的底部边界，在标题与搜索栏之间形成不必要的横线。
- 解决方案：仅在插件管理页移除 `.plugin-head` 的底部边界，保留标题布局、搜索栏和搜索控件样式。
- 验证结果：通过 `npm run build` 与 `git diff --check` 验证；插件扫描、筛选和目录打开逻辑不变。
- 适用边界：仅影响插件管理页面标题区域，不改变其他页面的模块标题边界。

### 插件管理选中行粉红色竖线移除记录（2026-09-12）

- 背景：插件列表当前选中行左侧的粉红色竖线与页面的透明磨砂背景不协调，且形成额外的视觉强调。
- 解决方案：移除插件列表选中行及禁用选中行的左侧 `inset` 阴影；保留选中背景、焦点轮廓、插件详情和列表交互。
- 验证结果：通过 `npm run build` 与 `git diff --check` 验证；插件扫描、筛选、选中和启停逻辑不变。
- 适用边界：仅影响插件页面列表选中状态的装饰线，不改变插件状态语义或其他页面的选中样式。

类型标签来自扫描区域：`plugin`、`patcher`、`core`。当前扫描结果只把成功解析出非空 `BepInPlugin` GUID 的 DLL 纳入插件库；普通依赖程序集不会出现在列表中。

## 后端扫描规则

`GET /plugins?game_dir=&search=&category=&offset=&limit=` 扫描 `BepInEx/Plugins`、`BepInEx/patchers` 和 `BepInEx/core` 下的 DLL，但只读取 .NET 元数据，不加载或执行程序集。

返回内容包括：

- assembly 名称和版本；
- BepInEx 插件 GUID、名称和版本；
- 功能描述、描述来源、置信度和证据；
- BepInEx 依赖、适用进程、不兼容项和程序集引用；
- 文件路径、大小、修改时间和元数据错误；
- 总数、各类别数量、解析失败数、重复 GUID 数和带描述/依赖的数量。

插件描述优先使用程序集自带描述，其次使用已知插件目录；必要时结合 `config/*.cfg` 和 `Translation/**/*.txt` 进行补充。重复 GUID 显示为诊断状态，不自动合并。

## 缓存

扫描结果复用主 SQLite 文件中的 `bepinex_plugin_cache` 表。缓存指纹包含启用/禁用形态的插件 DLL（包括 `.dl_`、历史 `.dll.disabled` 和临时 `.dll.dl_`）、配置和翻译文件；文件大小或修改时间发生变化时自动失效。后端支持 `refresh=1` 强制重扫，供 UI 或排障使用。

## 当前边界

- 页面提供单个插件的启用和禁用，不提供删除 DLL、批量启停或编辑插件配置的操作。
- 插件描述不是插件运行时行为分析，不能替代 BepInEx 日志。
- 所选目录无效或没有 `BepInEx` 文件夹时，后端返回错误并由页面显示重试入口。
