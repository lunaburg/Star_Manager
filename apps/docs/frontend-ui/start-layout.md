# 开始页布局

## 目标

开始页是左侧导航栏的第一项，用于完成游戏启动前的核心操作：

- 选择并校验 HS2 游戏目录。
- 读取 `UserData/setup.xml`。
- 修改游戏基础配置。
- 保存配置前自动备份。
- 启动游戏、启动工作室或启动 VR 模式。
- 打开常用游戏目录。

第一版配置文件固定参考测试环境：

```text
D:\Workspace\code_workspace\Star_Manager\test\hs2\UserData\setup.xml
```

在真实游戏目录中，对应路径为：

```text
<game_dir>\UserData\setup.xml
```

## 参考布局

开始页参考 HS2 启动器风格，但需要改造成更清爽的 Star_Manager 桌面工具界面。

页面结构：

```text
+--------------------------------------------------------------------+
| 启动操作条                                                         |
| [开始游戏] [开始工作室] [开始 VR] [setup.xml 已读取] [未保存配置]   |
+----------------------+-----------------------------+---------------+
| 游戏配置             | 启动器视觉卡                  | 目录入口       |
| - 语言               |                             | - 游戏主目录   |
| - 画质               |                             | - UserData     |
| - 显示器             |                             | - 工作室场景   |
| - 分辨率             |                             | - 截图         |
| - 全屏               |                             | - 人物卡女     |
| - 其他开关           |                             | - 人物卡男     |
+----------------------+-----------------------------+---------------+
| 底部：更新/外链/版本信息/运行日志入口                              |
+--------------------------------------------------------------------+
```

## 启动操作条

顶部提供三个主操作和配置状态：

- 开始游戏。
- 开始工作室。
- 开始 VR。
- `setup.xml 已读取` 状态徽标。
- `存在未保存配置` 状态徽标。


交互规则：

- 如果游戏目录无效，启动按钮禁用。
- 如果配置文件读取失败，启动按钮仍可用，但配置区显示错误状态。
- 启动前如存在未保存配置，提示用户保存或放弃修改。
- 启动失败时写入运行日志。

## 游戏配置区

左侧配置区读取并编辑 `setup.xml`。当前预览中该区标题为“游戏配置”，副标题为“读取 UserData/setup.xml”。

当前 `setup.xml` 字段：

```xml
<Setting>
  <Size>1920 x 1080 (16 : 9)</Size>
  <Width>1920</Width>
  <Height>1080</Height>
  <Quality>2</Quality>
  <FullScreen>false</FullScreen>
  <Display>0</Display>
  <Language>0</Language>
</Setting>
```

控件映射：

- `Language`：语言选择器。
- `Quality`：画质选择器，例如低、中、高、超高；具体枚举需由实现侧根据游戏实际值映射。
- `Display`：显示器选择器。
- `Size`、`Width`、`Height`：分辨率选择器。保存时必须同步写入三个字段。
- `FullScreen`：全屏复选框。


这些开关只有在后续确认对应配置文件和字段后才能启用；否则应显示为禁用或“未接入”。

当前预览中的控件顺序：

- 语言。
- 画质。
- 显示器。
- 分辨率。
- 全屏开关。
- 保存配置。

## 启动器视觉卡

中间列保留一个启动器风格视觉卡，用于延续 HS2 启动器的识别感，但不承载关键操作。

视觉卡规则：

- 可以使用品牌图形、封面预览、版本信息或启动状态。
- 不放置高风险文件操作。
- 不放置必须点击才可完成的主流程按钮。
- 允许在功能未定时保持为空白视觉占位，但尺寸应稳定，不挤压左右两列。

## 配置保存规则

保存配置前必须：

- 校验 `setup.xml` 存在。
- 使用 XML 解析器读写，避免字符串拼接。
- 保留 XML 编码，当前测试文件为 `utf-16`。
- 保存前创建备份，例如 `setup.xml.bak` 或带时间戳的备份文件。
- 写入失败时恢复 UI 状态，并把错误写入运行日志。

保存按钮状态：

- 无修改：禁用。
- 有修改：显示“保存配置”。
- 保存中：显示进度或 loading。
- 保存成功：显示轻量成功提示，并写入运行日志。


## 右侧说明与目录入口

右侧区域展示常用目录快捷按钮。当前预览标题为“目录入口”，副标题为“常用游戏目录快捷打开”。

常用目录按钮：

- 游戏主目录。
- `UserData`。
- 工作室场景。
- 截图。
- 人物卡（女）。
- 人物卡（男）。

打开目录失败时写入运行日志。

## 底部信息区

开始页不显示底部低频入口占位条，避免在小窗口或缩放场景下露出被截断的下一块布局。运行日志入口保留在左侧导航栏。

## 数据需求

建议新增能力：

```text
GET  /game/setup
POST /game/setup
POST /game/launch
POST /game/open-path
```

`GET /game/setup` 返回：

- 游戏目录。
- setup.xml 路径。
- 是否存在。
- 解析后的字段。
- 原始读取错误，若有。

`POST /game/setup` 负责：

- 校验字段。
- 备份原文件。
- 写入 XML。
- 返回保存结果。

`POST /game/launch` 支持：

- `game`
- `studio`
- `vr`

`POST /game/open-path` 支持打开常用目录。

## 空状态和错误状态

未选择游戏目录：

- 显示选择游戏目录按钮。
- 禁用配置读取和启动操作。

找不到 `setup.xml`：

- 配置区显示错误。
- 提供重新选择目录或重新读取按钮。

XML 解析失败：

- 不允许保存。
- 显示错误摘要。
- 提供打开文件所在目录和复制错误信息。

保存失败：

- 保留用户修改。
- 显示错误。
- 写入运行日志。
