# 总览页布局

## 当前职责

总览页把当前已建立的本地索引、实用工具、最近任务和本地成就放在一个两列工作区中。HS2 目录是否有效由顶部全局栏显示；总览不再单独维护一个重复的目录状态卡。四个一级内容容器不显示外部黑色边框，内部摘要卡、成就卡、操作项和任务项仍保留各自的细边框。

### 总览资源统计扩展记录（2026-09-16）

- **背景**：总览资源摘要原先只展示人物卡、模组和物品，无法快速查看服装卡、场景卡及 BepInEx 插件规模。
- **解决方案**：复用现有服装卡树、场景卡树和插件扫描接口，在有效游戏目录初始化时读取服装卡、场景卡和插件总数，并将三项加入总览摘要卡；点击服装卡或场景卡统计可直接进入对应卡片子界面，点击插件统计进入插件管理。
- **数据边界**：服装卡仅在独立有效性索引完成后显示有效总数；场景卡按 `UserData/studio/scene` 目录树统计；插件数量使用插件扫描返回的 `summary.total`，只包含成功解析出 `BepInPlugin` GUID 的程序集。
- **验证结果**：通过 `npm run build`、`git diff --check` 和源码数据源检查验证；切换游戏目录、目录无效或扫描失败时会清空对应统计，不沿用旧目录数值。
- **适用边界**：仅增加总览摘要统计和对应跳转，不改变服装卡、场景卡、插件扫描、数据库索引或插件启停行为。

### 总览六个统计卡高度收紧记录（2026-09-16）

- **背景**：总览页六个资源统计卡的纵向留白偏大，压缩了下方内容的可视空间。
- **解决方案**：将总览专属统计卡最小高度由 `108px` 调整为 `90px`，同步收紧内边距和标题与数量之间的间距；保留六卡布局、统计内容和点击跳转。
- **验证结果**：通过 `npm run build` 和 `git diff --check` 验证；六个统计卡高度降低，文字和交互保持正常。
- **适用边界**：仅影响总览页资源统计卡的视觉尺寸，不改变统计数据来源、卡片排列规则或其他页面卡片样式。

### 总览六个统计卡顺序调整记录（2026-09-16）

- **背景**：资源统计卡的排列顺序与用户查看资源类型的顺序不一致。
- **解决方案**：将摘要卡按“人物卡、服装卡、场景卡、模组、物品、插件”顺序生成；各卡的数据条件、统计来源和点击跳转保持不变。
- **验证结果**：通过 `npm run build`、`git diff --check` 和源码顺序检查验证；统计卡按指定顺序显示，缺少某类数据时其余卡片仍按相对顺序排列。
- **适用边界**：仅影响总览页摘要卡的排列顺序，不改变卡片数量、统计数据、布局尺寸或其他页面。

### 总览最近任务改为滚动列表记录（2026-09-12）

- 背景：最近任务原先最多保留 5 条，较早完成的任务会从总览页中消失，无法继续查看。
- 根因：前端 `rememberTask()` 使用 `.slice(0, 5)` 截取任务数组。
- 解决方案：移除前端的 5 条截取限制，为最近任务面板增加固定工作区内的纵向滚动容器和可见滚动条；任务仍按最近更新顺序排列。
- 验证结果：通过 `npm run build` 与 `git diff --check` 验证；任务列表超出面板高度时可通过滚动条查看较早任务，同一任务更新不会重复显示。
- 适用边界：任务记录仍仅存在当前前端会话内，不改变后端任务存储、任务执行或运行日志行为。

### 总览最近任务单项保持原高度记录（2026-09-12）

- 验证结果：通过 `npm run build` 与 `git diff --check` 验证；单个任务项不再填满容器，多条任务超出高度时仍可滚动查看。
- 适用边界：仅调整总览页最近任务列表的行高与滚动布局，不改变任务排序、数量或任务状态展示。

## 资源摘要

`overviewSummaryCards` 只在目录有效且对应数据源已经检查成功时生成卡片：

- 人物卡：`stats.cards`，跳转到角色管理；
- 服装卡：服装卡树返回的有效 `total`，跳转到卡片管理的服装卡子界面；
- 场景卡：场景卡树返回的 `total`，跳转到卡片管理的场景卡子界面；
- 模组：`stats.zipmods`，跳转到模组管理的模组浏览；
- 物品：`stats.modItems + stats.builtinItems`，跳转到模组管理的物品浏览；
- 插件：插件扫描返回的 `summary.total`，跳转到插件管理。

数据库未建立、卡片/插件统计尚未加载或目录无效时，主区域显示“暂无可用统计”，提示选择有效目录并创建数据库；已完成检查的统计卡可以独立显示。

## 实用工具

当前实现按顺序提供：

1. **导入外部模组**：选择外部目录，提交 `import_external_zipmods`；后端会识别标准结构的 `.zip` 并将导入副本规范为 `.zipmod`，同时处理松散 Unity3D、AIS 角色卡和服装卡。无效 `.zip` 会在结果面板列为跳过项，外部原文件保留不动。
2. **一键整理**：确认后提交 `organize_all_zipmods_by_author`，把 `mods/` 下的 zipmod 移入作者目录并刷新数据库。
目录无效或后端未就绪时，相关操作应保持禁用或由主壳层返回明确错误；重建数据库继续由顶部全局操作提供。

## 最近任务

最近任务显示前端已经记录的任务，包括导入、整理、数据库、角色卡批量操作和模组批量操作。任务数量不再限制为 5 条；超出面板可用高度时，通过面板内纵向滚动条查看较早任务。列表按提交顺序固定排列，最新提交的任务位于上方；进度轮询、错误和完成状态只更新原任务所在行，不会将其重新置顶。每行显示任务标题、由 `taskSummary()` 生成的简短结果和 `Done`/百分比/`Error` 状态。任务行是可点击按钮，点击后打开任务详情抽屉，展示状态、完成指标、开始/结束时间、完整任务消息；`build_mod_database` 额外展示原版资源索引、zipmod 扫描、物品解析、数据库写入、人物卡数据库和总耗时。任务快照仅保留在当前前端会话内，不通过单独的总览接口加载。

### 最近任务详情与数据库耗时汇总记录（2026-09-14）

- **背景**：数据库重建日志只有阶段进度消息，没有阶段耗时汇总；总览页最近任务只能查看摘要，无法回看任务完成情况。
- **根因**：后端任务状态没有 `finished_at` 或结构化计时字段，前端 `rememberTask()` 只保存标题、摘要和状态徽标，最近任务条目也不是可交互控件。
- **解决方案**：`build_mod_database` 记录并返回六项毫秒耗时：原版资源索引、zipmod 扫描、物品解析与缩略图、模组数据库写入、人物卡数据库和总耗时；完成时向任务消息追加秒数汇总。任务状态新增 `finished_at`。总览页保存任务快照，将最近任务行改为可点击按钮，并通过玻璃化右侧抽屉展示耗时、数据库统计、任务消息和时间信息。
- **验证结果**：通过 Python 语法检查、`npm run build` 和 `git diff --check` 验证；任务接口契约同步记录于 `apps/docs/backend-interface.md`。
- **适用边界**：任务历史仍是当前前端会话内存数据；应用重启后不会恢复旧任务。缩略图 profiling 文件仍保留单个物品级诊断记录，与任务详情中的阶段耗时汇总互补。

### 总览最近任务按提交顺序固定记录（2026-09-16）

- **背景**：最近任务列表使用任务状态更新时间排序，进度轮询会将正在执行的任务反复移动到列表顶部。
- **根因**：`rememberTask()` 每次接收任务快照时都将当前条目重新插入数组首位。
- **解决方案**：为每次提交分配本地提交序号；新任务按最新提交在上方的顺序插入，已有任务更新时保留原数组位置。并发提交时也依据提交序号而不是 HTTP 响应先后排列。
- **验证结果**：通过 `npm run build`、`git diff --check` 和源码顺序检查验证；任务进度、错误和完成状态更新不再改变最近任务的位置。
- **适用边界**：仅影响总览页最近任务的前端排列方式，不改变任务执行、轮询、详情抽屉或后端任务存储。

## 本地成就

成就陈列柜位于左侧摘要下方，不增加一级导航。当前后端定义五项里程碑：

- 收藏家：收录 1,000 张人物卡；
- 完美主义者：完成一次依赖完整的角色卡资源库扫描；
- 考古学家：发现同一 GUID 的三个文件版本；
- 整理大师：清理 10 GB 重复资源；
- 急救医生：修复 100 个缩略图或资源异常。

五项成就分别使用对应的 64×64 像素徽章图标：收藏家使用收藏宝箱，完美主义者使用金色桂冠与完成标记，考古学家使用带放大镜的档案盒，整理大师使用分类收纳柜，急救医生使用医疗十字与药瓶。图标资源位于 `apps/src/assets/achievement-*.png`，通过 `apps/src/achievementIcons.js` 按成就 ID 映射；成就 ID 和本地解锁记录保持不变。

点击成就后打开的详情抽屉采用横向头部：徽章位于左侧，成就名称位于徽章右侧，描述与进度信息从头部下方开始。

数据只存储在本地 SQLite。用户可以在总览或设置页调整显示/记录偏好；关闭“隐藏未解锁成就”可查看所有项目；点击项目会打开右侧详情抽屉，详情仅展示状态和首次解锁时间。关闭成就记录后，不再记录新的修复或清理事件。

## 空状态和错误状态

- 未选择有效目录：显示选择目录和创建数据库的引导，不显示伪造的统计数字。
- 数据库为空：保留建议操作，提示重建数据库。
- 后端不可用：保留静态页面结构，禁用需要后端的动作并显示日志错误。
- 最近任务为空：不渲染“最近任务”面板，避免空容器占据空间。
