# 设置页布局

## 目标

设置页集中管理 Star_Manager 自身的启动行为、资源检查策略、应用壁纸、人物卡主题、人物卡读取内容偏好、本地成就偏好、默认导出目录、便携依赖包偏好以及外部工具路径。设置保存在 Electron 用户数据目录的 `settings.json`，不是 HS2 的 `UserData/setup.xml`。

## 当前分区

页面目前包含六个区块：

1. **启动与检查**：启动页面、启动时是否检查 zipmod/人物卡资源变化；默认启动页为“开始游戏”。
2. **应用壁纸**：选择图片或 MP4。图片支持 PNG/JPG/WebP/GIF，视频静音循环播放；清除自定义路径后恢复内置默认壁纸。
3. **收藏人物卡主题**：`gold`、`neon`、`sakura`、`obsidian` 四种主题，统一控制收藏卡框、名字铭牌/字体和详情卡面效果。
4. **本地成就**：启用记录、解锁通知、隐藏未解锁项目，以及重置本地成就记录。
5. **默认导出位置**：通用导出目录、服装卡导出目录、便携依赖包目录；同时设置便携包默认 ZIP/文件夹输出。
6. **外部工具**：选择、替换或清除 `blender.exe` 和 SB3Utility 可执行文件的路径。

所有设置变更都会立即调用 Electron 的 `saveSettings`，页面显示保存成功或失败提示。便携依赖包的五类模组选择在生成弹窗中调整，并与压缩偏好和目录一起持久化。

## 持久化字段

`apps/electron/main.cjs` 的 `normalizeSettings()` 会限制合法值并提供默认值。当前字段为：

```text
gameDir
inputDir
outputDir
workbenchAuthorId
workbenchWorkspacePath
workbenchProjects
coordinateExportDir
portablePackageDir
blenderExecutablePath
sb3utilityExecutablePath
portablePackageCompress
portablePackageTypes: face | hair | body | clothes | accessory
characterCardLoadOptions: face | body | hair | clothes | accessory | parameter
startupView: start | overview | characters | mods | workbench | plugins | logs | settings
favoriteCardTheme: gold | neon | sakura | obsidian
checkDatabaseChangesOnStartup
wallpaperPath
wallpaperType: image | video
```

旧设置中的 `favoriteCardFrameTheme` 会迁移到 `favoriteCardTheme`；非法主题和启动页会回退到默认值。旧的 `cardNameEffect`、`cardBorderEffect` 不再参与当前界面。

`characterCardLoadOptions` 是所有人物卡共用的读取区块选择，首次使用默认包含六个区块；在读取弹窗中勾选或取消后立即保存，后续打开其它人物卡或重启应用都会沿用该选择。允许保存空数组，但读取时仍需至少勾选一项。

## 本地成就

成就数据单独保存在 SQLite 的 `achievement_progress`、`achievement_events` 和 `achievement_preferences` 表中。成就统计覆盖人物卡数量、零缺失扫描、同 GUID 版本、重复资源清理空间和资源修复次数。关闭成就后不再记录新的事件；重置只清理成就进度和事件，不删除资源索引。

## 与其他页面的边界

- 开始页的 `UserData/setup.xml` 配置区由 Electron 单独读写，不属于设置页 `settings.json` 的持久化字段；保存时会生成 `.bak` 并同步 Unity 注册表值。
- 工作台更换通用导出目录会复用设置页的 `outputDir`。
- 工作台作者 ID、工作空间路径、当前工程 ID 和已创建项目记录保存在同一份 Star_Manager 用户设置中；项目工程本身的 `star-manager.project.json` 和 `manifest.xml` 位于用户选择的工作空间内，前者用于工程识别，后者保存模组元数据。
- 外部工具区域同时管理 Blender 和 SB3Utility 可执行文件路径；路径会保存到 Electron 用户设置中，清除后需要重新选择才能使用对应工具。
- 角色卡主题的详细 CSS 和模板规则见[人物卡收藏视觉状态](character-card-favorite-effects.md)。

### 自定义 PNG 破图修复记录（2026-09-12）

- **现象**：选择包含中文或特殊字符的 Windows PNG 路径后，设置页预览与全局壁纸显示破图。
- **根因**：渲染器直接拼接 `file:///` 路径时，Electron 页面环境对本地路径编码与访问存在兼容性问题。
- **解决**：新增 `wallpaper:readImage` IPC，在主进程读取图片并返回带 MIME 的 data URL；MP4 仍使用本地文件 URL，避免将视频整体读入内存。
- **验证**：重新选择 PNG 后即时刷新预览，构建与 Electron 语法检查通过。

### MP4 动态壁纸路径修复记录（2026-09-12）

- **现象**：选择 MP4 后设置显示“已配置”，但视频预览和全局动态壁纸没有反应。
- **根因**：本地媒体 URL 构造函数在生成 `file:///` 后误删了协议前缀，Windows 路径因此被浏览器当作相对路径解析。
- **解决**：保留 `file:///` 协议并逐段编码路径，同时保留盘符冒号；MP4 使用该 URL 直接由 `<video>` 静音循环播放。

### MP4 跨开发/打包环境加载修复记录（2026-09-12）

- **现象**：修正路径格式后，开发模式下 MP4 仍可能显示空白。
- **根因**：开发渲染器运行在 HTTP origin，浏览器对跨 origin 的 `file://` 媒体流有限制。
- **解决**：注册 Electron `wallpaper://` 特权协议，由主进程通过 `net.fetch` 代理本地文件流；渲染器仅传递经过编码的本地路径，视频仍支持原生分段加载、静音和循环播放。

### 启动壁纸首屏切换修复记录（2026-09-15）

- **现象**：打包版启动时先显示无壁纸，再显示内置默认壁纸，最后才显示设置中的自定义壁纸。
- **根因**：应用挂载后才异步读取管理器设置，图片壁纸还会先清空 data URL 再异步读取文件，导致壁纸源连续变化。
- **解决**：preload 阶段同步取得启动壁纸配置，`App.vue` 用该配置初始化壁纸状态；图片与视频均使用 `wallpaper://` 本地文件流，不再把图片转换为启动用 data URL。Electron 窗口等待 renderer 壳层首帧后显示，壁纸媒体随后淡入；失败时回退默认壁纸，并以超时兜底保证异常 renderer 不会永久阻塞启动。
- **验证**：通过 `npm run build`、Electron 语法检查及打包版冒烟启动验证；自定义壁纸路径有效时首屏直接进入目标壁纸，设置页预览仍复用同一壁纸源。
- **适用边界**：设置保存格式和壁纸运行时切换行为不变；外部文件不存在或媒体解码较慢时会回退/延迟显示，窗口最多等待约 5 秒后按兜底策略显示。

### 首屏黑屏与媒体加载观感优化记录（2026-09-15）

- **现象**：启动时可能先看到黑色空窗；等待自定义壁纸加载也会让首屏可见时间偏晚。
- **根因**：透明 Electron 原生窗口在 renderer 首帧前可能被 Windows 合成为黑色；壁纸文件解码不应阻塞应用壳层显示。
- **解决**：原生窗口保留纯白 `#ffffff` 启动底色以避免首帧黑屏，但 Windows 标题栏覆盖区使用 `rgba(0, 0, 0, 0)` 透明色，并移除 renderer 右上角底板，使壁纸可以显示在原生按钮下方；壁纸未就绪时显示稳定的页面渐变底，媒体完成后短淡入。Electron 仅等待 renderer 首帧，不再等待外部壁纸解码。
- **验证**：通过 `npm run build`、Electron 语法检查和打包版冒烟启动验证；首屏不再出现透明黑底，壁纸加载慢时应用仍可立即看到稳定壳层。
- **适用边界**：外部图片/视频仍受文件大小与编码影响，首次解码完成后才显示；配置、选择、恢复默认和运行时壁纸切换逻辑不变。

## 设置页侧栏高亮按区块顶部同步记录（2026-09-12）

- **背景**：页面滚动时，侧栏相邻两个设置按钮会交替激活；期望只有对应设置区块滚动到内容区域顶部时才激活。
- **根因**：原逻辑使用 `IntersectionObserver` 观察视口中间的一段区域，并只比较当前回调中的 `entries`。相邻区块同时或交替进入该区域时，`activeSection` 会在两个区块之间来回切换。
- **解决**：改为监听设置内容容器的 `scroll` 事件，按区块顶部相对于内容容器顶部的位置计算当前区块，选择最后一个已经到达或越过顶部的区块；导航点击只触发滚动，不提前修改高亮状态。
- **验证**：通过 `npm run build`、`git diff --check` 验证；滚动高亮逻辑不再依赖交叉比例和中间观察区，区块排序、导航滚动及设置数据逻辑保持不变。
- **边界**：高亮基准是右侧设置内容滚动容器的顶部，不是浏览器窗口顶部；响应式布局下仍沿用同一顶部判定规则。
