# Star_Manager 项目介绍

Star_Manager 是一个面向 HS2 / AIS 本地游戏目录的桌面资源管理器。它把角色卡、zipmod、模组物品、BepInEx 插件和资源诊断集中到一个 Electron 桌面应用中，通过本地 Python 后端建立可重建的索引，帮助用户查找、预览、整理和维护游戏资源。

本文是面向新用户、项目协作者和需要快速了解产品边界的人的入口文档。页面说明已根据当前可运行版本实际打开各主页面后的界面和无障碍文本核对；动态数量、目录状态和任务进度以用户本机显示为准。

![Star_Manager 品牌标志](../build-resources/brand-logo.png)

## 一句话理解

选择一个 HS2 游戏目录后，Star_Manager 会扫描 `mods/` 与 `UserData/chara/`，建立本地数据库，再通过多个页面提供浏览、诊断、导出和维护能力。

## 它主要解决什么问题

- 在大量角色卡中按目录、名称、标签和收藏状态查找内容。
- 在 zipmod 与模组物品之间切换浏览，查看作者、版本、状态、缩略图和来源包。
- 发现缺失资源、缩略图异常、重复 GUID、坏包和角色卡依赖问题。
- 批量整理、导出或修复资源，并在运行日志中跟踪任务进度。
- 查看 BepInEx 插件的元数据、版本、依赖和诊断信息。
- 将 Sims 4 Package 资源提取为适合后续制作的 FBX/PNG 资源，并在配置 Blender 后进行 HS2 对齐的 T-Pose 固化。

它不是联网的模组分发平台，也不执行 BepInEx DLL，不把本地成就上传到服务器。数据库、缩略图和预览文件属于可以重新生成的本地运行时缓存。

## 从页面理解产品

| 页面 | 主要用途 | 用户通常在这里做什么 | 需要注意的边界 |
| --- | --- | --- | --- |
| 开始游戏 | 设置游戏目录并启动 HS2 相关程序 | 选择目录、检查目录有效性、启动游戏/工作室/VR、打开常用目录 | `setup.xml` 区域目前是界面配置入口/占位能力，不应当当作已经完成的 XML 写回契约 |
| 总览 | 查看资源库健康状况 | 查看角色卡、zipmod、物品数量，查看成就、建议操作和最近任务 | 数量来自本地索引；首次启动或索引变化时可能需要等待任务完成 |
| 角色管理 | 浏览 `UserData/chara` 下的 AIS/HS2 角色卡 | 切换当前目录/卡片库、按目录查找、搜索、查看详情、依赖、标签、收藏和批量操作 | 当前目录、索引是否完成和卡片类型会影响列表数量 |
| 模组管理 | 浏览 zipmod 与其物品 | 在模组浏览/物品浏览间切换，按使用状态、作者和状态筛选，查看详情、诊断、预览和维护入口 | 单对象操作与批量任务的确认和进度路径不同；移动/删除会影响游戏目录 |
| 插件管理 | 查看 BepInEx 插件库存 | 搜索名称/GUID/DLL，查看版本、类型、状态、依赖、适用进程和诊断，打开 BepInEx 目录 | 当前边界是只读扫描和缓存，不会执行或启停插件 |
| 工作台 | 进行独立的模组制作辅助 | 选择 `.package`、选择输出目录、提取 LOD0 FBX 和全部色板，生成 HS2 对齐的 T-Pose 纯网格 | 未选输入文件时提取按钮不可用；Blender 是可选集成，最终结果会清理骨骼和蒙皮 |
| 运行日志 | 观察启动和任务过程 | 按类型筛选、搜索、清空、复制或导出日志，排查失败和进度问题 | 日志记录的是当前运行会话及任务消息，不替代后端接口文档 |
| 设置 | 统一管理持久化偏好 | 选择启动页面、开关启动检查、选择收藏卡主题、管理成就、导出目录、便携包和 Blender 路径 | 设置影响后续启动和工具默认值；具体任务仍可能允许临时改目录 |

应用顶部的共享区域贯穿主要页面：它显示当前 HS2 目录、目录校验结果、后端状态和数据库任务进度，并提供全局“重建数据库”入口。

## 推荐使用流程

```mermaid
flowchart LR
    A["选择 HS2 目录"] --> B["目录有效 + Backend ready"]
    B --> C["检查或重建本地索引"]
    C --> D["总览确认数量与健康状态"]
    D --> E["浏览角色卡、模组和插件"]
    E --> F["复制式整理、导出或修复"]
    F --> G["运行日志跟踪任务结果"]
```

### 第一次打开

1. 在“开始游戏”或顶部共享区域选择 HS2 游戏目录。
2. 确认页面显示“目录有效”，并等待 `Backend ready`。
3. 如果页面提示索引不存在、过期或正在构建，等待任务完成；必要时使用“重建数据库”。
4. 打开“总览”确认角色卡、zipmod 和物品数量，再进入具体资源页面。
5. 第一次执行整理或导出时，优先保留“Copy”模式，先验证输出结果，再考虑移动操作。

### 日常整理

1. 在“角色管理”中按目录、名称或标签找到目标卡片，查看卡片详情和依赖。
2. 在“模组管理”中先查看警告/错误数量，再选择 zipmod 或物品视图定位问题。
3. 对单个对象使用详情页提供的操作；对多个对象使用批量任务，并在“运行日志”观察进度。
4. 发现重复 GUID、缺失 Unity3D 或缩略图问题时，先查看诊断信息，再决定修复、导出、合并或删除。
5. 在“插件管理”中只把扫描结果作为库存和诊断参考，插件本身仍由游戏/BepInEx 管理。

## 各页面的实际能力

### 开始游戏

页面包含 HS2 目录选择、目录有效性提示、数据库任务状态、后端状态和三个启动入口：`HoneySelect2.exe`、`StudioNEOV2.exe`、`HoneySelect2VR.exe`。右侧快捷入口可打开游戏主目录、`UserData`、工作室场景、截图目录和男女角色卡目录。

页面中的游戏配置区域会展示 `UserData/setup.xml` 相关的语言、画质、显示器、分辨率和全屏项。当前项目仍将这部分视为渲染层配置入口/占位功能，若要修改 XML 读写行为，应先查看代码和接口现状，不要仅根据页面控件推断功能已经接通。

### 总览

总览把索引结果压缩为三个核心数量卡：角色卡、模组和模组物品。下方的本地成就陈列柜展示整理、修复和收藏里程碑；右侧建议操作会把常见任务引导到外部导入、一键整理、重建数据库、角色管理或模组管理。最近任务区域用于确认目录检查、数据库构建等任务是否完成。

### 角色管理

角色管理以 `UserData/chara` 为根，右侧目录树显示各目录及数量，中间区域提供当前目录/人物卡库切换、搜索和多选。选择角色卡后可以进入详情，查看封面、基础信息、依赖、标签、收藏、评分和相关操作；批量场景使用任务协议处理移动、标签、删除或依赖包导出。

如果页面显示“未找到人物卡”，先确认当前目录是否正确、卡片索引是否完成，再切换到卡片库或重新选择目录。不要把某一个空目录的结果误认为整个 `UserData/chara` 没有卡片。

#### 人物卡侧边详情栏工具

![当前版本人物卡详情栏实机截图](assets/character-detail-screenshot.png)

> 实机截图：当前版本的“角色管理”页面，右侧详情栏已打开“关联”页签。截图中的卡片数量、路径、依赖数量和卡片内容会随本地游戏目录变化。

选中人物卡后，右侧栏可在“详情 / 关联 / 工具”之间切换。工具和信息的职责如下：

| 工具或区域 | 作用 | 写回/输出边界 |
| --- | --- | --- |
| 收藏星标 | 收藏或取消收藏当前人物卡；收藏主题会同步影响网格卡框和详情卡面 | 收藏元数据写入人物卡 PNG 的 `KKEx` 区块，不依赖 SQLite |
| 替换封面 | 选择 PNG/JPG/WebP，在 `63:88` 裁剪框中调整可见封面 | 只替换 IEND 前的可见 PNG，人物卡尾部数据和插件数据保留 |
| 评分 | 直接选择 1–5 星 | 保存当前人物卡评分 |
| 标签 | 添加、编辑或新建标签；批量标签在浏览器工具栏中处理 | 单卡直接写回；批量追加使用任务并保留原有标签 |
| 人物参数 | 编辑姓名、性格、生日、声线和 `futanari`；性别只读 | 写回当前 PNG，并在写回后重新校验卡片 |
| 关联 | 按服装、配饰、面部、发型、身体等部位查看依赖，区分已匹配、物品缺失和模组未安装 | 点击依赖项可跳转到对应物品或缺失处理流程 |
| 设为看板娘 | 将当前卡写入 `navi` 或 `sitri` 看板娘槽位 | 直接写入对应游戏目录的看板娘文件 |
| 导出为服装卡 | 将当前卡识别出的服装、配饰和坐标级插件数据导出为服装卡 | 可配置目录；未配置时按性别写入 `UserData/coordinate/female` 或 `male`，不会覆盖同名文件 |
| 生成便携依赖包 | 按选定依赖类型复制人物卡、匹配 zipmod、外部 Unity3D 和依赖清单 | 可输出 ZIP 或文件夹；只复制文件，不移动原始资源 |

### 模组管理

模组管理顶部显示 zipmod 数量、物品数量、warnings、errors 和最近索引时间。主区域有“模组浏览”和“物品浏览”两种视图，并支持已使用、未使用、全部等使用状态筛选；表格中还可以按作者、状态和搜索条件缩小范围。右侧详情面板承载 GUID、来源文件、诊断、缩略图、模型预览和维护操作。

项目把 zipmod 作为包级对象、`abdata/list/**/*.csv` 解析出来的内容作为物品级对象。两者的数据库关系、重复 GUID 主副本规则和增量重建方式，统一以[模组数据库设计](mod_manage/mod_database_design.md)与[数据库变更检测](mod_manage/mod_database_change_detection.md)为准。

#### 模组物品侧边详情栏工具

> 实机操作路径：进入“模组管理”→“物品浏览”，选中一条物品记录后，在右侧详情栏打开“工具”页签。这里的工具会根据当前物品和本地资源状态显示 3D 预览、来源模组、FBX 导出、缩略图和删除等操作；本文不再使用示意图代替实机截图。

在“物品浏览”中选中一行后，右侧栏包含“详情 / 工具”两个页签：

| 工具或区域 | 作用 | 重要限制 |
| --- | --- | --- |
| 详情信息 | 查看来源模组、完整 GUID、物品 ID、分类表和依赖 Unity3D 文件 | 这是数据库和解析结果，不等于重新扫描文件 |
| 3D 模型预览 | 按需生成并加载模型，支持旋转、缩放、平移、背景和灯光预设 | 游戏专用 Shader 可能降级为标准材质；模型失败不应阻塞其他详情 |
| 定位来源模组 | 跳转到模组浏览并选中当前物品所属的 zipmod | 这是应用内定位，不是删除或移动操作 |
| 导出 FBX 模型 | 导出当前物品的静态网格、材质和贴图，完成后打开文件位置 | 需要选择目标目录；不包含骨骼和动画 |
| 重建缩略图 | 在外部 PNG 和当前 3D 预览截图之间选择来源并写回缩略图 | 使用 3D 截图前必须先成功加载模型 |
| 批量缩略图工具 | 导出当前物品缩略图，或选择当前已加载列表中的缺失缩略图物品并批量应用 | 批量应用使用任务协议，目标范围受当前加载/筛选列表限制 |
| 删除物品 | 删除当前 `mod_items` 记录及对应资源处理 | 会修改游戏目录和数据库，必须经过确认；执行前应备份 |

### 插件管理

插件管理扫描游戏目录下的 BepInEx 插件 DLL，并在列表中显示插件名称、GUID、版本、类型和识别状态。输入框支持按插件名称、GUID 或 DLL 搜索；选中一项后，右侧显示描述、依赖、适用进程和诊断信息，顶部按钮可以打开 BepInEx 目录。

扫描结果是只读库存信息。Star_Manager 不执行 DLL，也不负责启用、禁用或修改插件配置；如需调整插件行为，应回到 BepInEx/游戏自身的管理方式。

### 工作台

当前工作台以 `Package → FBX` 为主：

1. 选择 Sims 4 `.package` 源文件。
2. 选择输出目录。
3. 提取模型的最高顶点数 LOD0，并解码 RLE2/DXT5 色板为 PNG。
4. 配置 Blender 后，可使用内置 165 骨骼 TS4 模板和 GEOM 原始权重，将模型固化为 HS2 对齐的 T-Pose。
5. 输出阶段清理 Armature、骨骼、顶点组和蒙皮，得到适合后续使用的静态纯网格 FBX。

页面目前会在未选择 `.package` 时禁用提取按钮；后续工具卡片仍属于扩展位。完整输入输出边界和 Blender 集成约定见[工作台页面说明](frontend-ui/workbench-layout.md)。

### 运行日志

运行日志以时间顺序展示后端启动、目录检查、数据库扫描、任务提交、进度、完成和失败消息。页面提供任务类型筛选、搜索、清空、复制全部和导出入口。处理大规模 zipmod 库时，日志是判断“仍在运行”“已完成”还是“失败退出”的首选位置。

### 设置

设置页面按功能分为四组：

- 启动与检查：选择下次启动页面、控制启动时是否比较 zipmod/角色卡索引。
- 收藏人物卡主题：在鎏金流彩、霓虹炫彩、樱落绮梦和黑曜鎏火之间选择统一的卡框、铭牌字体、详情卡和动态效果。
- 本地成就：启用成就陈列柜、解锁通知、隐藏未解锁成就，或重置本地记录。
- 默认导出与 Blender：设置通用导出目录、服装卡导出目录、便携依赖包目录、ZIP 压缩偏好，以及 Blender 可执行文件路径和 RIG/AUTO IMPORT 集成。

收藏主题、成就和导出目录属于本地持久化设置，不会改变 zipmod 数据库本身。

## 数据与安全边界

- 所有索引、预览、日志和成就记录都存放在本地；运行时后端默认通过 `http://127.0.0.1:8765` 提供服务。
- SQLite、缩略图和卡片预览是可重建缓存。更换游戏目录或发现索引落后时，应通过应用重建，而不是手工编辑缓存文件。
- 文件操作默认使用 `Copy`。`Cut`、移动、合并和删除会改变游戏目录，执行前应确认目标和备份策略。
- 单个文件或对象使用直接 HTTP 路由；批量处理使用 `/tasks`，并通过任务状态和运行日志报告进度。接口细节见[前后端接口约定](backend-interface.md)。
- 插件页面只扫描元数据；角色卡依赖解析、zipmod 诊断和 Unity3D 修复属于不同的资源流程，不要把它们混为同一个“插件修复”功能。

## 常见问题

### 为什么总览有数量，角色或模组页面却暂时为空？

页面列表是异步分页加载的，且角色管理还受当前目录/卡片库选择影响。先等待顶部任务和页面加载结束，再检查当前目录、搜索条件和筛选条件。

### 什么时候需要重建数据库？

首次选择目录、检测到 zipmod 或角色卡发生变化、列表与文件系统明显不一致，或日志提示索引过期时，可以执行重建。普通启动会先做变更检测，未发现变化时不必每次全量重建。

### 工作台为什么不能直接提取？

必须先选择 `.package` 文件和输出目录；如果需要 HS2 对齐 T-Pose，还要在设置中配置可用的 Blender 可执行文件。

### 日志里的任务一直没有结束怎么办？

先确认任务仍在增加进度，再检查磁盘空间、游戏目录访问权限和日志中的具体异常。大规模 zipmod 库首次构建可能需要较长时间；不要在任务尚未完成时重复提交同一批量任务。
