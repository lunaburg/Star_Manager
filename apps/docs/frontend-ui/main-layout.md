# 主布局

## 目标

主布局定义 Star_Manager 的通用应用外壳。界面应让用户首先感受到“资源库浏览器”，其次才是“任务运行器”。

用户的主要目标：

- 选择 HS2 游戏目录。
- 在开始页查看当前游戏启动入口，并编辑 `UserData/setup.xml` 的游戏显示配置。
- 启动游戏、打开工作室或打开常用游戏目录。
- 扫描并浏览资源。
- 查看角色卡、zipmod、模组物品、诊断和任务结果。
- 默认执行基于 `Copy` 的安全工作流。

## 应用外壳

应用壳层在所有页面最底层维护一个不可交互的壁纸媒体层。默认使用内置插画；用户可在设置中选择图片或 MP4，自定义文件以 `settings.json` 中的 `wallpaperPath` / `wallpaperType` 加载。侧栏、顶部栏和工作区内容保持在媒体层之上。

### 启动壁纸首屏切换修复记录（2026-09-15）

- **现象**：打包版启动时先显示无壁纸，再显示内置默认壁纸，最后才显示设置中的自定义壁纸。
- **根因**：Vue 壁纸状态初始为空，应用挂载后才异步读取 `settings.json`；图片还会额外经过一次 `readWallpaperImage` IPC 转为 data URL，造成连续的源切换。
- **解决**：Electron 在 preload 阶段通过同步 IPC 只读取启动所需的壁纸路径和类型，Vue 首次渲染直接使用已保存配置；本地图片和 MP4 统一通过 `wallpaper://` 协议加载，移除启动时的 data URL 中间态。窗口默认隐藏，等待原生首帧和 renderer 壳层就绪后显示；媒体加载失败时回退内置壁纸，并保留启动超时兜底。
- **验证**：通过 Electron/Vue 构建、Node 语法检查和打包版启动冒烟测试验证；有效自定义壁纸不再经过默认壁纸中间态，后端与 renderer 正常启动。
- **适用边界**：仅影响应用启动时的壁纸首屏与窗口显示时机，不改变设置字段、壁纸选择、图片/视频格式支持或运行时切换逻辑；大型视频仍受其自身解码时间影响，超时后会显示窗口并继续加载。

### 首屏黑屏与媒体加载观感优化记录（2026-09-15）

- **现象**：启动时透明原生窗口在 renderer 首帧前可能显示为黑色；若等待外部壁纸解码，首屏又会被大图片或视频拖慢。
- **根因**：Electron `BrowserWindow` 使用透明背景，Windows 合成空档会暴露黑色底；壁纸媒体不应成为应用壳层可见的前置条件。
- **解决**：原生窗口保留纯白 `#ffffff` 的启动底色，用于 renderer 首帧前避免黑屏；Windows 标题栏覆盖区改为明确的透明 RGBA，移除 renderer 右上角的白色底板，让原生按钮下方直接显示壁纸。壁纸层在外部媒体完成前使用与页面一致的渐变底，自定义媒体就绪后以短淡入显示。renderer 只在首帧完成后通知 Electron 显示窗口，后端和壁纸继续异步预热。
- **根因补充**：此前为处理黑屏而同时将 `titleBarOverlay.color` 和 renderer 底板设为纯白，导致启动窗口虽不再黑屏，但原生按钮区必然遮住壁纸；启动底色与标题栏覆盖色需要分别配置。
- **验证**：通过 Vite 构建、Electron 语法检查和打包版启动冒烟测试验证；窗口不再依赖壁纸解码才能显示，启动期间不会暴露透明黑底。
- **适用边界**：外部壁纸的首次解码时间仍取决于文件大小和视频编码，但它只影响壁纸淡入时机，不阻塞应用壳层显示；自定义文件不存在时仍回退内置壁纸。

## 左侧导航栏

左侧栏是主导航，在所有模块中保持可见。

导航项：

- 开始游戏
- 总览
- 卡片管理
- 模组管理
- 插件管理
- 工作台
- 回收站
- 运行日志
- 设置（固定在侧栏底部）

左侧栏行为：

- 当前预览宽度为 250 px，实际实现可在 240-280 px 内微调。
- 开始页固定为第一项，用于配置游戏和启动游戏。
- 品牌区保留 `Star Manager` 品牌图，移除独立应用图标；导航项图标继续保留。
- 当前模块使用柔和粉色到浅蓝的高亮背景，不使用选中态外部黑色边框或偏移阴影。
- 每个导航项使用图标加短文字；工作台使用工具箱图标，其他模块继续使用当前业务图标。
- 卡片管理项右侧展示三个互斥的 SVG 类型按钮，分别切换人物卡、服装卡和场景卡子界面；人物卡使用完整浏览器，服装卡使用 `UserData/coordinate` 的独立扫描、增量索引和详情链路，场景卡使用 `UserData/studio/scene` 的独立扫描、分页、虚拟网格和详情链路，场景卡预览比例为 `320:180`。
- 左侧栏不固定显示安全上下文，也不放“导出诊断信息”入口。
- 设置入口固定在导航底部，与资源管理模块分隔；管理器自身的启动行为、本地记录和默认导出位置在此集中修改。

### 回收站导航顺序调整记录（2026-09-17）

- 背景：回收站入口位于运行日志之后，文件恢复入口不便于在资源管理流程中快速定位。
- 根因：`App.vue` 的 `views` 数组将 `logs` 排在 `trash` 之前，侧栏按该数组顺序渲染。
- 解决方案：将 `trash` 调整至 `logs` 之前；页面路由、图标和回收站加载逻辑保持不变。
- 验证结果：通过 `npm run build` 与导航数组顺序检查验证。
- 适用边界：仅调整左侧主导航的显示顺序，不改变回收站和运行日志的功能、状态缓存或设置入口位置。

### 导航品牌区移除独立应用图标记录（2026-09-12）

- 背景：导航栏品牌区中的独立方形应用图标与 `Star Manager` 品牌图并列显示，视觉信息重复。
- 根因：应用壳层品牌区同时渲染 `.brand-mark` 应用图标和 `.brand-logo` 品牌图。
- 解决方案：移除 `.brand-mark` 模板节点及其资源导入，仅保留 `.brand-logo`；各导航项自己的 `.nav-icon` 不变。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；品牌区不再显示独立应用图标，导航项图标和切换行为保持正常。
- 适用边界：仅影响左侧导航品牌区，不删除应用图标资源文件，也不改变导航项图标、导航逻辑或窗口图标配置。

### 导航品牌图放大居中记录（2026-09-12）

- 背景：移除独立应用图标后，品牌图仍沿用原有预留图标空间的宽度约束，显示偏小且视觉上偏左。
- 根因：`.brand` 未设置水平居中，`.brand-logo` 仍使用 `calc(100% - 60px)` 的旧尺寸约束。
- 解决方案：将品牌区设置为水平居中，并将品牌图显示区域调整为 `min(190px, 100%) × 68px`，保留 `object-fit: contain` 以适配横向图形。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；品牌图放大并居中显示，导航项布局和交互保持不变。
- 适用边界：仅影响左侧导航品牌图的显示尺寸与对齐方式，不改变品牌资源内容、导航项图标或导航逻辑。

### 选中导航项移除黑色阴影记录（2026-09-12）

- 背景：选中导航项右下方的黑色偏移阴影过重，红框中的“总览”按钮与导航栏背景形成明显的硬阴影分隔。

### 卡片管理导航项移除黑色边框记录（2026-09-12）

- 背景：卡片管理导航项外层的黑色选中边框包住主按钮和卡片类型切换按钮，视觉层级过重。

### 所有导航选中按钮移除黑色边框记录（2026-09-12）

- 背景：模组管理等主导航项在选中状态下仍显示黑色外框，与无阴影的导航视觉不一致。
- 根因：通用 `.nav-entry.active` 仍保留选中边框；卡片类型按钮的 active 状态也单独使用了黑色边框。
- 解决方案：将所有 `.nav-entry.active` 和 `.nav-card-type-button.active` 的边框设置为透明，保留选中背景、导航图标轮廓和卡片类型选中提示。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；所有导航按钮选中时不再显示黑色外部边框，导航和卡片类型切换保持正常。
- 适用边界：影响导航主项及卡片类型按钮的选中态边框，不改变导航项图标自身边框、悬停态边框或导航逻辑。

### 导航选中按钮移除粉色焦点竖线记录（2026-09-12）

- 背景：点击导航后，选中按钮右侧仍出现一条粉色竖线，与已移除的选中边框和阴影不一致。
- 根因：`.nav-entry` 保留 `2px solid transparent` 边框时，选中态渐变不会绘制透明边框区域，右侧边框占位会露出侧栏底色，形成粉色竖线；该现象不是浏览器焦点 `outline`。
- 解决方案：将 `.nav-entry` 和导航主按钮的边框本身设为 `0`，让选中态渐变完整铺满导航项；同时保留焦点 `outline` 和 `box-shadow` 清除规则，避免其它浏览器焦点装饰重新出现。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；点击导航后不再显示右侧粉色焦点竖线。
- 适用边界：仅影响主导航项和底部设置项的透明边框占位及焦点装饰，不改变卡片类型按钮、导航布局或页面切换行为。

### 导航按钮图标移除黑色边框记录（2026-09-12）

- 背景：导航按钮左侧的业务图标仍带有黑色方形边框，与当前轻量化导航视觉不一致。
- 根因：`.nav-icon` 使用通用 `var(--line-strong)` 绘制 `2px` 黑色边框。
- 解决方案：将 `.nav-icon` 的边框设为 `0`，保留固定尺寸、图标轮廓、颜色和选中态背景，避免文字与导航项布局变化。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；导航主按钮左侧图标不再显示黑色方形边框。
- 适用边界：仅影响主导航与底部设置导航的左侧业务图标，不改变导航按钮、卡片类型切换按钮自身及页面切换逻辑。

### 侧栏品牌区与设置区移除分隔线记录（2026-09-12）

- 背景：侧栏 Logo 下方和底部“设置”入口上方的两条横向分隔线使侧栏内容被切成明显的上下区块，与当前连续的半透明玻璃侧栏视觉不一致。
- 根因：`.brand` 使用 `border-bottom: 1px solid var(--line)`，`.nav-secondary` 使用 `border-top: 1px solid var(--line)`。
- 解决方案：移除这两个分隔线声明；保留品牌区内边距、设置入口底部对齐方式和导航布局。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；Logo 下方及设置入口上方横线消失，导航切换和设置入口位置保持不变。
- 适用边界：仅影响侧栏品牌区与设置区之间的两条横线，不改变页面内容区域、其它模块分隔线或按钮边界。

## 顶部全局栏

顶部栏展示全局状态和全局操作，不重复承担模块导航。

设置页例外：进入设置页时不渲染全局顶部栏，并回收其布局高度，让设置页侧栏和设置区块从应用工作区顶部开始显示；目录、任务、Backend 状态和数据库重建操作仍可从其它页面使用。

总览页例外：进入总览页时不渲染全局顶部栏，并回收其布局高度，让资源摘要、实用工具、成就陈列柜和最近任务从应用工作区顶部开始显示；目录、任务、Backend 状态和数据库重建操作仍可从开始页使用。

模组浏览例外：进入模组管理的“模组浏览”时不渲染全局顶部栏，并回收其布局高度，让模组表格和详情抽屉从应用工作区顶部开始显示。物品浏览仍使用顶部栏作为类别筛选栏，装配模式仍使用装配顶部栏；目录、任务、Backend 状态和数据库重建操作仍可从开始页使用。

- **验证**：通过 `npm run build` 和 `git diff --check` 验证；设置页工作区占满可用高度，其他页面的顶部栏逻辑未改变。
- **边界**：仅影响 `activeView === 'settings'` 时的应用外壳展示，不改变设置字段、持久化或全局操作本身。

- **边界**：仅影响 `activeView === 'overview'` 时的应用外壳展示，不改变目录选择、数据库重建、任务进度或总览摘要/工具逻辑。

### 模组浏览移除全局顶部栏记录（2026-09-17）

- 当前游戏目录选择器，文案为“选择 HS2 目录”。

## 共享后端上下文

当前后端任务路由继续有效：

- `GET /health`
- `GET /tasks`
- `GET /tasks/:id`
- `POST /tasks`

当前 `POST /tasks` 支持数据库、卡片、zipmod 导入/导出/整理、角色卡批量维护和缩略图批量维护等任务。完整 task type、payload 和结果字段以[前后端接口](../backend-interface.md)为唯一契约；主布局只记录页面会触发的几个关键任务：

- `check_game_dir`：选择目录后校验 HS2 结构。
- `build_mod_database`：顶部全局进度条专用，增量建模组库后继续更新角色卡库。
- `import_external_zipmods`：总览页导入外部 zipmod、松散 Unity3D、角色卡和服装卡。
- `organize_all_zipmods_by_author`：总览页一键按作者整理 `mods/`。
- `export_character_dependency_package`：角色卡详情生成便携依赖包。
- 角色卡/模组批量删除、标签、移动、修复和导出任务：在对应页面提交并由最近任务/日志反馈。

当前模组资源库浏览接口：

- `GET /mods/database`：检查本地模组数据库是否存在，并返回 zipmod 与物品计数。
- `GET /mods/zipmods?offset=&limit=&author=&status=&usage=`：分页读取 zipmod 列表，当前前端首批 200 条。
- `GET /mods/zipmods/authors`：读取模组作者筛选项。
- `GET /mods/zipmods/:id/diagnostics`：读取当前 zipmod 的 manifest、Unity3D、缩略图和重复文件诊断。
- `GET /mods/items?offset=&limit=&zipmod_id=&search=&kind=&author=&status=&usage=&source=&game_dir=`：分页读取物品列表；`source=all` 与 `game_dir` 用于物品浏览中的模组/游戏本体合并查询，带 `zipmod_id` 时用于模组详情的物品 tab。
- `GET /mods/items/filters?game_dir=`：读取物品作者和 Kind 筛选项，原版筛选项按当前游戏目录限定。
- `GET /mods/thumbnails?path=`：读取运行时缩略图缓存，仅允许访问缩略图目录。
- `GET /plugins?game_dir=&search=&category=&offset=&limit=`：读取 BepInEx 插件库。
- `POST /plugins/toggle`：直接启用或禁用一个 BepInEx 插件，后端通过可逆 DLL 重命名完成，目标文件已存在时拒绝覆盖。
- `GET /achievements`：读取总览成就和设置页本地成就偏好。
- `POST /tasks` with `build_mod_database`：重建模组和角色卡数据库，后端会拒绝无效 HS2 游戏目录。
- 单项模组、物品和角色卡修改走直接 HTTP；批量操作统一走 `/tasks`。完整接口见[前后端接口](../backend-interface.md)。

当前角色卡库接口：

- `GET /library/cards/tree?game_dir=`：读取 `UserData/chara` 目录树和 AIS PNG 计数。
- `GET /library/cards?game_dir=&path=`：读取当前目录直属 AIS 人物卡，不递归子目录。
- `GET /library/cards/image?game_dir=&path=`：读取人物卡图像或标准化预览缓存。

当前实现边界：

- 游戏、工作室、VR 启动以及开始页的 `setup.xml` 读取、校验、UTF-16 保存和 `.bak` 备份已通过 Electron IPC 接通；启动时还会检测 IPA/BepInEx 框架冲突。
- 角色卡详情、依赖、收藏、评分、标签、封面、坐标卡和便携依赖包已接通。
- 运行日志目前是前端内存数组；筛选、复制和导出控件仍有占位行为，没有独立日志 HTTP API。

## Electron IPC 边界

前端通过 `window.desktopApi` 访问桌面能力：

- `selectDirectory`、`selectImageFile`、`selectWallpaperFile`、`selectImageForCrop`、`selectBlenderExecutable`：选择目录、PNG 缩略图、图片/MP4 壁纸、封面裁剪输入和 Blender 可执行文件。
- `showItemInFolder`：在资源管理器中定位选中文件。
- `launchGameExecutable`：启动游戏、工作室或 VR 可执行文件。
- `loadGameSetup`、`saveGameSetup`：读取和写回 `UserData/setup.xml`，提供显示器/分辨率选项，并同步 Windows Unity 注册表值。
- `openFbxInBlender`：启动用户配置的 Blender，并在空场景中导入工作台生成的 FBX。
- `loadSettings`、`saveSettings`：保存游戏目录、导出目录、便携包偏好、启动页、收藏主题、自动检查和 `blenderExecutablePath` 等本地偏好。
- `backendRequest`：访问本地 Python HTTP API。

## 高风险规则

所有会修改游戏目录的操作都必须使用统一的高风险确认流程。

高风险示例：

- `move/cut`。
- 删除文件或目录。
- 修改游戏目录结构。
- 在原游戏目录内批量整理。
- 删除空目录。

确认弹窗必须展示操作名称、影响数量、源路径、目标路径、是否可恢复，以及明确的确认按钮，例如 `确认移动 128 个 zipmod`。
