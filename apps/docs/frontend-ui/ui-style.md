# UI 风格规范

## 方向

Star_Manager 应像一个轻量、友好的桌面资源管理器。当前设计方向是“柔和桌面工具 + 透明磨砂玻璃层 + 语义化控件”：粉蓝强调、壁纸透叠、低对比边缘高光和清晰的资源管理层级。

界面可以可爱，但必须让用户相信它适合管理真实文件。玻璃效果服务于层次和连续性，不能牺牲文字可读性、状态识别或文件操作的安全感。

## 视觉原则

- 使用稳定的左侧导航列。
- 模块内容保持明亮、留白充足，并优先使用统一的半透明磨砂表面。
- 资源浏览优先使用卡片。
- 只有在需要精确扫读时使用表格。
- 详情和日志默认不要占据主视觉路径。
- 高风险操作绝不能表现得像轻量 toggle。
- 外层页面容器不使用重复的黑色粗边框或装饰性分隔线；内部卡片和高风险控件仍可保留必要边界。
- 控件可以有一点玩具感，但信息架构必须像可靠的文件管理工具；状态变化应通过语义色、细边缘、轻微高光和柔和过渡表达。

## 界面文字极简原则

- 界面只保留完成当前任务所必需的文字；能通过布局、图标、状态色或控件形态表达的内容，不再重复写成说明。
- 页面标题、区块标题、按钮、标签和 Tab 优先使用短词或“动词 + 对象”，删除语气词、套话、重复对象名和装饰性标语。
- 同一语义在不同页面使用同一套短命名；不要为了显得完整，在每个控件旁重复页面标题、当前筛选或操作结果。
- 空状态、提示和错误信息先给结论，再只保留用户下一步所需的信息；详细解释放入 tooltip、详情区或日志，不占据主操作路径。
- 图标按钮只有在含义不明确时提供 tooltip；tooltip 也应是简短的动作或对象名称，不写成操作教程。
- 极简不等于省略关键信息：风险操作仍须明确影响范围、对象和确认动作，错误状态仍须说明原因和可执行的恢复入口。

## 色彩

推荐角色：

- 应用背景：冷调浅蓝到白色，再过渡到极浅粉色；有壁纸时允许背景图像透过磨砂层参与层次。
- 玻璃表面：使用低不透明度的冷白/背景混合色，而不是大面积纯白填充。
- 玻璃边缘：使用半透明白色细边和低对比内沿高光，避免形成硬框。
- 主强调色：柔和粉色，用于当前导航和选中分类。
- 次强调色：浅蓝色，用于主按钮、当前导航图标和积极操作。
- 安全状态：青绿色或绿色。
- 警告状态：琥珀色。
- 高风险状态：红色。
- 文本：主文本近黑，次要文本使用柔和灰。

避免让整个应用变成单一粉色主题。粉色用于引导注意，而不是覆盖所有界面。

当前共享玻璃变量：

- `--glass-border: rgba(255, 255, 255, .68)`；
- `--glass-background-fallback: rgba(247, 251, 255, .2)`；
- `--glass-background: color-mix(in srgb, var(--bg-color) 20%, transparent)`；
- `--glass-shadow: inset 0 -1px 0 rgba(177, 188, 198, .18)`。

使用 `color-mix()` 时必须保留可工作的半透明回退值；玻璃表面同时使用 `backdrop-filter: blur(...)` 时，应控制模糊和对比度，避免文字边缘发灰。

## 字体

中英文界面文本使用系统 UI 字体。

推荐尺寸：

- 页面标题：20-24 px。
- 区块标题：16-18 px。
- 正文：13-15 px。
- 元数据和徽标：12-13 px。
- GUID、路径和日志：等宽字体。

不要根据视口宽度缩放字体。标签应短而稳定。

## 左侧栏

左侧栏样式：

- 宽度：当前预览 250 px，可在 240-280 px 内调整。
- 背景：冷白到浅蓝的半透明磨砂表面，与当前壁纸连续衔接。
- 面板：侧栏使用无外边缘、灰白半透明磨砂表面（背景模糊、轻微内阴影）和约 16 px 圆角；侧栏容器和主导航业务图标不设置外层黑色边框，必要的按钮描边与选中态提示按控件语义保留。
- 品牌区只显示 `Star Manager` 品牌图，不显示独立应用图标；品牌图放大并水平居中。
- 当前项：柔和粉色到浅蓝渐变背景，不使用选中态外部黑色边框、偏移阴影或点击后右侧焦点竖线。
- 图标加文字，图标为两字母缩写。
- 如果增加二级分组，使用清晰分组标题。

导航项文字不应换行。如果文字太长，应缩短标签。

侧栏只承载品牌和主导航，不固定显示安全上下文区域，也不放“导出诊断信息”入口。

## 顶部全局栏

顶部全局栏样式：

- 高度当前预览为 76 px。
- 使用半透明磨砂表面、圆角和无外层黑色边框；内部控件根据操作语义保留细边缘或状态色。
- 左侧放 HS2 目录选择和当前路径，中间放任务进度，右侧只放单一全局操作“重建数据库”。
- 路径和任务 ID 使用等宽字体或稳定数字字形。
- 任务进度条保持细而清晰，不抢过模块内容。

页面级主容器与侧栏共享 `color-mix(in srgb, var(--bg-color) 20%, transparent)` 半透明磨砂表面、12px 背景模糊和低对比内阴影；不使用顶部内高光，避免圆角容器边缘出现白色亮线。卡片类型、工作台等容器可在该表面上叠加低对比主题光晕，但不应恢复为高不透明度纯白背景。

## 卡片

资源卡片：

- 圆角约 12-18 px；人物卡可使用更明确的 14-18 px。
- 卡片主体可使用浅色或半透明表面；资源缩略图和名称条优先保证对比度。
- 外层页面容器不使用黑色粗描边和实体投影；资源卡片可按选中、收藏或风险状态保留必要的强调边界和阴影。
- 状态徽标放在一致位置。
- 资源主名称清晰可见。
- 元数据放在名称下方成组展示。

角色卡片应强调大缩略图，并在底部使用浅粉或浅橙信息条显示名称。Zipmod 卡片应强调名称、作者、GUID 和状态。

人物卡选中态只使用右上角圆形勾选徽章，不额外增加粗边框、底部状态条或“已选”文字。

## 工具栏

工具栏控件：

- 搜索输入框放左侧。
- 筛选器紧随搜索。
- 排序和视图控件放右侧。
- 模块操作放最右侧。

刷新、打开目录、导出、切换视图等低频操作不放在顶部全局栏；如在模块工具栏或详情区使用图标按钮，仅图标按钮需要 tooltip。

人物卡浏览器标题栏右侧不放 `REF`、`LG`、`...` 这类孤立小按钮；刷新属于模块工具栏或状态变化触发，视图密度和排序属于工具栏。

人物卡浏览器的标题区域和工具栏与下方卡片区域共享浏览器面板背景，不额外叠加独立色带、内沿高光或底部边界。批量选择、全选、标签范围、搜索和筛选控件使用轻量玻璃控件：

- 中性控件使用透明白色层、浅色细边和轻微模糊；
- 移动、标签、删除、提取等操作保留低透明度语义色，不使用大面积实色；
- 数量徽标与父按钮使用同色系半透明层，避免突兀的黑色圆框；
- 悬停、键盘聚焦、标签范围切换和语义色变化使用约 180-240ms 的柔和过渡；
- 聚焦仍须有清晰可见的轮廓，不得为了“无边界”而移除可访问性提示。

工具栏控件的玻璃适配只应使用页面或模块范围选择器，不能覆盖其他页面的按钮、输入框和筛选器。

## 透明表面与边界

- 页面级容器优先使用统一玻璃表面，不重复绘制标题底线、外框和内框。
- 总览页的资源摘要、成就、建议操作和最近任务四个一级面板不显示外部边框；建议操作与最近任务的列表项使用更轻的玻璃层，以维持可点击区域识别。
- 总览页成就陈列柜不使用标题计数装饰，卡片网格与标题之间保留适度顶部留白。
- 人物卡浏览器顶部区域不单独形成横向色带，顶部与下方网格使用同一背景层；内部控件可通过细边缘、语义色和状态过渡保持可辨识度。
- 删除边界时必须保留卡片、按钮、输入框、风险操作和键盘聚焦的必要识别线索。

## 状态过渡

- 普通 hover/focus 状态使用背景亮度、边缘高光和轻微光晕变化，不使用突兀的纯色跳变。
- 重要状态（删除、错误、警告）可以使用红色或琥珀色，但应控制为半透明色层并保持文本对比度。
- 状态变化只改变视觉层，不改变布局尺寸；避免因边框宽度、投影或文字粗细变化导致控件跳动。
- `prefers-reduced-motion: reduce` 时应降低或关闭标签滑块、卡片入场和状态切换动画。

## 详情抽屉

详情抽屉应：

- 固定宽度约 360-440 px。
- 顶部展示选中资源标题。
- 分组展示元数据、依赖、路径和操作。
- 在用户浏览时保持打开，并随选择变化更新内容，避免频繁弹窗打断。

只在确认、阻塞错误或聚焦表单时使用模态弹窗。

## 角色卡目录

角色卡库的右侧区域优先用于“卡片目录”，而不是常驻详情抽屉。

卡片目录样式：

- 固定宽度约 280-340 px。
- 标题为“卡片目录”。
- 使用树形层级展示 `UserData/chara`。
- 节点数量使用柔和粉色徽标。
- 当前选中节点使用浅灰或浅粉底。
- 展开/折叠按钮保持小而清晰。
- 目录树独立滚动，底部可提供隐藏/收起按钮。

## 风险状态

高风险 UI 必须明显区分：

- 红色或琥珀色风险标题。
- 清楚解释将要改变什么。
- 影响文件数量。
- 源路径和目标路径。
- 可用时提供更安全的替代操作。
- 具体确认按钮文案。

示例：

- `确认移动 128 个 zipmod`
- `确认删除 14 个空目录`
- `确认整理游戏目录中的文件`

避免使用 `OK`、`Yes`、`确定` 这类泛化确认文案。

## 空状态

空状态应具体且有用。

示例：

- 未选择游戏目录：显示预期 HS2 文件夹和目录选择器。
- 未建立索引：显示扫描操作。
- 当前文件夹没有角色卡：显示选中文件夹路径。
- 后端不可用：显示重试操作，并禁用后端操作。

## 参考图适配

可借鉴参考图中的：

- 柔和侧边栏。
- 粉色当前导航。
- 图标化分类网格。
- 上方浏览、下方或右侧详情信息的分区工作区。
- 模块标题栏附近的紧凑工具按钮。

不要借鉴：

- 会员、积分、云商城或游戏化经济元素。
- 将高风险文件操作做成随手可点的 toggle。
- 与 Star_Manager 工作流无关的纯装饰控件。

## 像素风格层

当前预览在“桌面资源管理器 + 透明玻璃表面”的基础上保留少量像素风格，而不是转成完整游戏菜单。

- 背景使用 16px 网格或低对比重复纹理，不能影响表格、路径和 GUID 的阅读。
- 主面板、顶部栏和侧栏使用玻璃表面与细边缘，不恢复统一粗黑外框。
- 硬边块状投影只用于明确的选中卡片、风险确认或需要强提示的状态；玻璃工具控件使用低对比阴影和内沿高光。
- 按钮保留明确按压反馈，但移动距离以 1-2px 为主，避免布局跳动。
- 分段控件、tab 组、筛选组和按钮行的父容器使用细边、半透明底或留白分组；状态滑块可以使用柔和光晕，不使用硬投影。
- 表格选中行、tab 组、筛选组和普通信息块不使用条纹背景；像素感主要通过硬边、低圆角、网格背景和少量缩略图纹理表达。
- 头像、缩略图和占位图使用 `image-rendering: pixelated`，但正文、表格和日志文本保持清晰。
- 像素化只作为视觉材质，不改变信息密度、风险分区和安全确认规则。

## CSS 维护记录：清理未使用样式

2026-09-12 对 `apps/src/styles.css` 做了当前源码范围内的静态引用检查。此前设置页、总览页、插件页、服装卡、装配页和重复模组弹窗曾多次改版，样式文件中残留了旧 DOM 结构对应的规则。

- 根因：页面结构更新后，旧 class 没有同步从全局样式文件移除；部分旧规则还会被后续规则覆盖，增加阅读和维护成本。
- 处理：删除当前 `apps/src` 模板和脚本中没有引用的旧样式；保留 `danger-action`、`merge-action` 等仍在使用的通用语义样式，以及通过 Vue `:class` 动态生成的 Kind、收藏主题和便携包类型样式。
- 后续复用：合并属性完全一致的状态、交互和提示规则，并抽取 `.text-ellipsis`、`.two-column-grid`、`.flex-between` 与 `.glass-surface--compact` 工具类；页面专属边框、圆角和语义色仍保留在组件选择器中。
- 验证：清理后静态扫描不再发现确定未引用的 CSS 类；动态类以其生成逻辑为准，不按字面搜索结果删除。
- 适用边界：该检查覆盖当前 Electron/Vue 源码，不覆盖运行时外部注入的 HTML 或未来页面。新增动态 class 时应同时检查静态扫描误报，并在删除样式前确认模板和 `:class` 绑定。
