# 运行日志布局

## 目标

运行日志用于查看应用运行过程、后端状态、任务提交、任务进度和错误消息。它替代“缺失资源”作为独立子布局，但缺失 zipmod、缺失 `abdata/unity3d` 等业务问题仍应在总览、角色卡库、Zipmod 库和运行日志中以状态或结果展示。

运行日志的定位是“现场记录”。它承担任务提交、进度、完成、失败和错误排障的主要查看入口。

## 展示形态

推荐使用独立工作区页面；从顶部全局栏打开时，也可以作为大尺寸弹出面板。当前预览采用完整工作区页面。

参考结构：

```text
+--------------------------------------------------+
| 运行日志                                      X   |
+--------------------------------------------------+
| [清空显示] [复制全部] [导出日志] [级别] [搜索] [自动滚动] |
+--------------------------------------------------+
|                                                  |
|  Ready.                                          |
|  [Mode] zipmod extract mode: Copy                |
|  [Backend] Python backend is ready.              |
|                                                  |
|                                                  |
|                                                  |
+--------------------------------------------------+
```

视觉要点：

- 白色外层面板。
- 顶部标题栏显示“运行日志”。
- 右上角可显示关闭按钮；作为侧栏导航进入时，关闭按钮行为等同返回上一个业务模块或保持当前页，由实现侧决定。
- 工具栏位于标题栏下方。
- 主体为深色终端区域。
- 终端区域使用等宽字体。
- 日志面板应有明确边框和阴影，保持桌面工具感。

## 入口

入口位置：

- 左侧导航栏：运行日志。
- 左侧导航栏或任务进度上下文：进入运行日志。
- 顶部任务迷你进度：点击后可打开运行日志并滚动到当前任务附近。

打开方式：

- 从左侧导航进入时，可作为完整工作区页面显示。
- 从任务进度上下文打开时，当前预览可直接跳转到运行日志工作区；后续也可以改为弹出面板覆盖当前工作区。
- 弹出面板关闭后不改变当前业务模块。

## 日志内容

日志应收集：

- 应用启动消息。
- 当前 zipmod 提取模式，例如 `Copy`。
- Python backend 健康状态。
- 用户选择路径的记录。
- 任务提交消息。
- 任务进度消息。
- 任务完成或失败消息。
- 后端错误和解析错误。
- 高风险操作确认结果。

消息示例：

```text
Ready.
[Mode] zipmod extract mode: Copy
[Backend] Python backend is ready.
[Path] 选择游戏路径: D:\HoneySelect2
[Task] Task submitted: search_cards
[Task Error] No AIS cards found in input directory.
```

## 工具栏

日志面板可提供轻量工具栏，但不应喧宾夺主。

控件：

- 清空显示。
- 复制全部。
- 导出日志。
- 按级别筛选：全部、Info、Warning、Error。
- 搜索日志文本。
- 自动滚动到底部开关。

如果空间不足，工具栏按钮可放在标题栏右侧或终端区域上方。

当前预览中搜索框示例值为 `Task`，自动滚动开关默认开启。

## 交互规则

- 新日志默认追加到底部。
- 如果用户滚动到历史位置，不应强制跳回底部，除非开启自动滚动。
- 清空显示只清空前端当前日志视图，不删除后端任务记录或诊断文件。
- 错误日志应有醒目标记，但不要破坏终端整体可读性。
- 日志内容很长时必须支持滚动。
- 关闭弹窗不应清空日志。

## 数据需求

初版可以继续使用前端本地日志数组和任务轮询消息。

后续可新增接口：

```text
GET  /logs
POST /logs/export
POST /logs/clear-view
```

其中 `clear-view` 只代表清空当前 UI 显示，不删除任务历史或后端诊断文件。
