# 运行日志布局

## 当前职责

运行日志是一个完整工作区页面，用于查看前端本地记录的启动、后端健康检查、路径选择、任务提交、任务进度、完成和失败消息。它不是后端持久化日志，也不替代模组/角色卡详情中的诊断信息。该页面隐藏应用壳层的全局顶部栏，并回收其布局高度；日志容器自身不显示外部边框，标题栏和工具栏内部的分隔线仍保留。

## 当前布局

```text
+--------------------------------------------------+
| 运行日志                                          |
+--------------------------------------------------+
| [清空显示] [复制全部] [导出日志(禁用)]              |
+--------------------------------------------------+
|                                                  |
|  Ready.                                          |
|  [Mode] zipmod extract mode: Copy               |
|  [Backend] Python backend is ready.              |
|                                                  |
+--------------------------------------------------+
```

主体使用高模糊半透明终端玻璃区域和等宽字体；日志由 `ctx.logs` 数组按顺序渲染，文字使用近黑色以保持清晰度。

运行日志外层容器使用高模糊半透明玻璃背景，标题栏、工具栏和终端区域复用同一玻璃层。

## 当前交互和占位行为

- **清空显示**：清空当前 Vue 日志数组和已见任务消息，不删除后端任务状态或数据库。
- **复制全部**：当前只记录 `[Clipboard] copy placeholder`，尚未接入系统剪贴板。
- **导出日志**：当前按钮禁用。
- **自动滚动**：当前没有实现独立开关。

## 运行日志页面红框控件移除记录（2026-09-12）

- **背景**：界面参考要求移除运行日志页右上角关闭按钮，以及工具栏右侧未接入逻辑的级别下拉框和搜索框。
- **解决**：删除上述三个占位控件，保留日志标题、清空显示、复制全部、导出日志和终端内容；页面仍通过左侧主导航切换，不改变日志数组或清空逻辑。
- **验证**：通过 `npm run build`、`git diff --check` 和源码字符串检查验证。
- **边界**：仅调整运行日志页面的展示控件，不新增日志筛选、导出或关闭行为。

## 运行日志容器高模糊玻璃背景记录（2026-09-12）

- **背景**：界面参考要求运行日志页面红框标注的外层容器与壁纸保持连续的磨砂玻璃质感，并提高背景模糊度。
- **解决**：为 `.log-view` 增加半透明背景、`backdrop-filter: blur(30px)`、内沿高光和柔和阴影；标题栏与工具栏同步使用高模糊半透明层，终端区域保持独立显示。
- **验证**：通过 `npm run build` 与 `git diff --check` 验证；日志内容、清空显示、复制全部和导出按钮逻辑未改变。
- **边界**：仅影响运行日志页外层容器、标题栏和工具栏的背景材质，不改变终端日志颜色、日志数据或操作行为。

## 运行日志终端玻璃化记录（2026-09-12）

- **背景**：界面参考要求将运行日志区域原有的黑色背景改为模糊玻璃样式，并将日志文字改为黑色。
- **解决**：为 `.terminal` 增加浅色半透明玻璃背景、`backdrop-filter: blur(30px)`、细白边和柔和阴影；文字颜色调整为近黑色，保留等宽字体和日志滚动区域。
- **验证**：通过 `npm run build` 与 `git diff --check` 验证；日志数组、清空显示和复制全部逻辑未改变。
- **边界**：仅影响运行日志终端区域的背景、边界和文字颜色，不改变日志内容、按钮行为或外层容器布局。

## 运行日志工具栏按钮移除黑色边框记录（2026-09-12）

- **背景**：界面参考要求运行日志工具栏中“清空显示”“复制全部”“导出日志”三个按钮不显示黑色边框。
- **解决**：在 `.log-view` 范围内将工具栏三个按钮的边框设为 `0`，保留按钮文案、间距、禁用状态和原有操作逻辑。
- **验证**：通过 `npm run build`、`git diff --check` 和源码样式标记检查验证。
- **边界**：仅影响运行日志页工具栏的三个按钮，不改变其它页面工具栏按钮或日志终端区域。

因此文档和 UI 不应把“日志导出、持久化筛选、自动滚动”描述成已完成能力。

## 日志内容

当前常见消息包括：

- `Ready.`、zipmod 提取模式和后端启动状态；
- 选择游戏目录和目录校验结果；
- `Task submitted: <task_type>`；
- 轮询得到的任务消息、进度和错误；
- 数据库变动检测、自动增量重建、导入/整理/导出结果；
- 直接 HTTP 操作失败或文件定位失败。

任务完整状态仍通过 `GET /tasks/:task_id` 获取，前端轮询后把新消息追加到本地数组。

## 相关接口和代码

运行日志当前不请求独立日志 API，依赖：

```text
GET /health
POST /tasks
GET /tasks/:task_id
```

未来如果需要跨重启保存日志，可另行设计日志存储和 `GET /logs`；不能把前端数组直接当作稳定的后端接口契约。

- `apps/src/components/views/LogsView.vue`
- `apps/src/App.vue`：`log()`、任务轮询、`clearLogs()`
- `apps/backend/app/bridge.py`：任务消息和状态
