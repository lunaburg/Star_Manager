# 开始页布局

## 当前职责

开始页是左侧导航第一项，当前已经接通：

- 选择并保存 HS2 游戏目录；
- 通过 Electron 启动 HS2、Studio 和 VR；
- 打开游戏主目录、`UserData`、工作室场景、截图和男女角色卡目录；
- 展示一个面向 `UserData/setup.xml` 的游戏配置面板。

开始页下方的游戏配置、启动器视觉卡和目录入口三个一级容器不显示外部黑色边框；配置控件保留各自边框，目录入口按钮使用透明磨砂玻璃表面和浅色边缘高光，不使用黑色外边框。

### 开始页三个容器移除外部边框记录（2026-09-12）

- 背景：开始页三个并列一级容器的黑色粗边框过重，与页面工作区边界形成重复分隔。
- 根因：游戏配置、启动器视觉卡和目录入口都继承了通用 `.panel` 的 `3px` 外部边框。
- 解决方案：为 `.start-columns` 下的三个直接面板增加开始页专属覆盖规则，设置 `border: 0`；内部表单控件、快捷入口按钮和视觉卡内容保持不变。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；三个一级容器外部边框消失，开始页启动流程、配置读写和目录打开行为保持不变。
- 适用边界：仅影响开始页 `.start-columns` 下的三个一级 `.panel`，不改变启动操作条或其他页面容器的边框样式。

### 开始页标题区移除底部分隔线记录（2026-09-12）

- 背景： “游戏配置”和“目录入口”标题下方的横线与开始页当前连续的半透明容器视觉不一致。
- 根因：两个标题区域使用通用 `.module-head`，该规则默认设置 `border-bottom: 1px solid var(--line)`。
- 解决方案：增加 `.start-view .module-head` 覆盖，将开始页标题区底边框设为 `0`；保留标题、说明文字、内边距和下方控件布局。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；开始页两个红框位置的横线消失，配置和目录入口功能保持不变。
- 适用边界：仅影响开始页两个 `.module-head`，不改变其它页面标题栏或开始页表单控件、目录按钮样式。

### 开始页目录入口副标题移除记录（2026-09-12）

- 背景：目录入口标题下方的“常用游戏目录快捷打开”文字与右侧按钮列表的功能含义重复，占用标题区域空间。
- 解决方案：移除目录入口 `.module-head` 内的副标题，仅保留“目录入口”标题和目录快捷按钮。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；副标题消失，六个目录打开入口和布局保持可用。
- 适用边界：仅影响开始页目录入口标题区域，不改变其它页面的 `.subtext`、目录按钮或路径逻辑。

### 开始页目录入口按钮移除黑色外边框记录（2026-09-12）

- 背景：截图标注的“游戏主目录”“UserData”“工作室场景”“截图”和男女人物卡目录按钮仍显示黑色外边框，目录入口区域视觉重量偏重。
- 根因：六个目录入口按钮通过 `.quick-list button` 继承并覆盖了通用按钮边框，只将边框宽度调整为 `1px`。
- 解决方案：将 `.quick-list button` 的边框设置为 `0`，保留按钮的背景、文字对齐、间距、禁用状态和目录打开逻辑。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；目录入口六个按钮不再显示黑色外边框。
- 适用边界：仅影响开始页右侧目录入口按钮，不改变游戏配置控件、保存配置按钮、启动按钮或其他页面按钮的边框。

### 开始页目录入口按钮改为透明磨砂玻璃记录（2026-09-12）

- 背景：移除黑色外边框后，目录入口按钮仍使用全局白色实心背景，与开始页整体的半透明壁纸和玻璃容器层次不一致。
- 解决方案：为 `.quick-list button` 使用浅白半透明背景、8px 背景模糊和轻微白色内沿/外发光；悬停和键盘聚焦时仅提高玻璃表面亮度与边缘光晕，不恢复黑色边框。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；六个目录入口按钮可透出后方背景，边缘保持低强度浅色高光，目录打开行为不变。
- 适用边界：仅影响开始页右侧目录入口按钮的背景和边缘质感，不改变按钮尺寸、文案、间距、禁用状态或其它页面控件。

其中 `setup.xml` 面板由 Electron 主进程负责读取和写回真实文件。读取失败时不会覆盖用户文件；保存会先生成 `UserData/setup.xml.bak`，再以 UTF-16 编码原子写入 `UserData/setup.xml`，并同步 HS2 使用的 Unity 注册表值。

## 启动操作条

页面提供三个启动按钮：

- `开始游戏` → `HoneySelect2.exe`；
- `开始工作室` → `StudioNEOV2.exe`；
- `开始 VR` → `HoneySelect2VR.exe`。

未选择游戏目录或正在读取配置时按钮禁用。启动前如果存在未保存修改，会先保存 `setup.xml`；启动动作通过 preload 的 `launchGameExecutable(launchType, gameDir)` 进入 Electron 主进程。主进程检测 `IPA.exe` 与 `BepInEx\\core`：存在 IPA 时使用 `IPA.exe <target.exe> --launch`，否则直接启动目标 exe；同时检测到 IPA 和 BepInEx 时拒绝启动并写入运行日志。

### 开始页启动按钮移除黑色外边框记录（2026-09-12）

- 背景：截图标注的“开始游戏”“开始工作室”和“开始 VR”按钮仍显示黑色外边框，与顶部栏按钮的轻量化视觉不一致。
- 根因：三个启动按钮继承全局 `button` 的 `2px solid var(--line-strong)` 边框。
- 解决方案：为 `.launch-bar > button` 设置 `border: 0`，保留启动按钮的颜色、文字、禁用状态和启动逻辑。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；三个启动按钮不再显示黑色外边框。
- 适用边界：仅影响开始页启动操作条的三个按钮，不改变 setup.xml 状态徽标、配置控件、目录入口按钮或其它页面按钮。

### 开始页启动按钮改为透明磨砂玻璃记录（2026-09-12）

- 背景：启动按钮移除黑色边框后，仍使用普通实心按钮背景，与启动操作条及下方页面容器的半透明玻璃视觉不一致。
- 解决方案：为三个 `.launch-bar > button` 复用目录入口按钮的浅白半透明背景、背景模糊和轻微白色边缘发光；“开始游戏”保留浅蓝主按钮色阶，另外两个按钮使用浅白玻璃表面。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；三个启动按钮与启动操作条融合，悬停和聚焦时仅增强浅色边缘光晕。
- 适用边界：仅影响开始页三个启动按钮的背景和边缘质感，不改变启动逻辑、禁用状态、按钮尺寸或 setup.xml 状态徽标。

### 开始页次级启动按钮增强边界与悬停反馈记录（2026-09-12）

- 背景：透明磨砂处理后，“开始工作室”和“开始 VR”按钮的边界与鼠标悬停状态不够明显。
- 解决方案：为 `.launch-bar > button:not(.primary)` 增加低对比青灰色细描边；悬停和键盘聚焦时提高描边亮度、玻璃表面亮度和浅色光晕，并将按钮上移 `2px`，按下时回落 `1px`。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；两个次级启动按钮边界和交互状态更易辨识，启动逻辑不变。
- 适用边界：仅影响开始页“开始工作室”和“开始 VR”按钮，不改变“开始游戏”、setup.xml 状态徽标、配置控件或目录入口按钮。

启动操作条在开始页工作区内与上下相邻容器保持一致的垂直间距：上方工作区内边距和下方内容间距均为 `18px`。该页面专属间距不会改变其它页面的工作区布局。

顶部徽标反映真实读取状态、文件是否需要创建和 dirty 状态。

## 游戏配置区

当前控件为语言、画质、显示器、分辨率、全屏和保存按钮。字段会映射到原启动器使用的 XML 字段：

### 配置面板副标题移除记录（2026-09-11）

- 背景：游戏配置标题下方的“读取 UserData/setup.xml”文字与当前面板信息重复。
- 解决方案：移除该副标题，保留“游戏配置”标题、配置控件及真实读取状态徽标。
- 适用边界：仅调整开始页配置面板的文字层级，不改变 `setup.xml` 的读取、编辑和保存逻辑。

### 开始页保存配置按钮改为透明磨砂玻璃记录（2026-09-12）

- 背景： “保存配置”按钮仍继承全局按钮的黑色边框和 `var(--soft-shadow)` 偏移阴影，与开始页其它玻璃按钮的视觉不一致。
- 根因：`.wide-action` 未覆盖全局 `button` 边框，且继续使用通用实体阴影。
- 解决方案：为 `.start-view .wide-action` 移除边框和黑色阴影，改用浅蓝半透明背景、8px 背景模糊和轻微白色内沿/外发光；悬停时提升透明色阶和光晕并上移 `2px`，按下时回落 `1px`。
- 验证结果：通过 `npm run build` 和 `git diff --check` 验证；保存按钮呈现透明磨砂玻璃效果，保存配置功能不变。
- 适用边界：仅影响开始页“保存配置”按钮，不改变全屏开关、表单下拉框、启动按钮或其它页面的宽按钮。

```text
Language: integer
Quality: 0..2
Display: integer
Width / Height: integer
FullScreen: boolean
Size: "宽 x 高 (宽高比)"
```

分辨率下拉框包含原启动器的常用分辨率，并追加当前显示器桌面分辨率和 XML 中的自定义分辨率；显示器列表由 Electron `screen.getAllDisplays()` 提供。`Language`、`Quality`、`Display` 和 `FullScreen` 使用数值/布尔值写回，不把显示文本写入 XML。

## 启动器视觉卡和目录入口

中间视觉卡是品牌和启动状态展示区，不承载文件写入操作。右侧目录入口使用当前游戏根目录拼接相对路径：

| 文案 | 相对路径 |
| --- | --- |
| 游戏主目录 | `.` |
| UserData | `UserData` |
| 工作室场景 | `UserData\\Studio\\scene` |
| 截图 | `UserData\\cap` |
| 人物卡（女） | `UserData\\chara\\female` |
| 人物卡（男） | `UserData\\chara\\male` |

目录打开使用 `openDirectory()`。目标不存在或打开失败时只记录错误，不自动创建目录。

## 当前持久化边界

游戏目录和输入/输出目录等管理器设置通过 Electron `settings.json` 保存，详见[设置页布局](settings-layout.md)。HS2 游戏配置单独保存在游戏目录的 `UserData/setup.xml`，不写入管理器自身的 `settings.json`。

## 当前接口

开始页实际使用：

```text
POST /tasks { task_type: "check_game_dir" }
GET  /health
```

桌面能力使用：

```text
selectDirectory("选择 HS2 目录")
openDirectory(path)
loadGameSetup(gameDir)
saveGameSetup(gameDir, setup)
launchGameExecutable("game | studio | vr", gameDir)
```

`loadGameSetup` 和 `saveGameSetup` 是 Electron IPC，不是 Python HTTP 路由；它们负责 XML、备份、原子写入、显示器列表和 Windows 注册表同步。

## 空状态和错误状态

- 未选择游戏目录：保留页面结构，禁用启动按钮和目录入口。
- 目录校验失败：顶部显示目录无效，依赖游戏目录的浏览和任务操作由主壳层禁用。
- 启动文件不存在或启动失败：保持页面可用，并在运行日志中显示错误。
- `setup.xml` 解析错误：显示错误摘要，阻止写回源文件并禁用启动按钮。
- `setup.xml` 保存错误：保留 dirty 状态，阻止启动，直到用户修复或重新选择目录。
- 注册表同步失败：XML 仍会保留已生成的备份和新配置，但页面显示警告，便于用户处理权限或系统问题。
